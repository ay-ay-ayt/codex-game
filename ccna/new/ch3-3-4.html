3-3 OSPFv2（シングルエリア）

頻出設定 CCNA最重要トピック。OSPFの動作・設定・確認を完全マスターする

🌐OSPFの基本概念

OSPF（Open Shortest Path First）はリンクステート型のIGP（内部ゲートウェイプロトコル）です。Dijkstraアルゴリズム（SPFアルゴリズム）で最短経路を計算します。

OSPFの基本パラメータ 値 説明
AD値 110 他のIGPより優先度が低い（EIGRP=90より高い数値）
メトリック コスト 参照帯域幅÷インタフェース帯域幅（デフォルト参照BW=100Mbps）
プロトコル番号 89 TCPでもUDPでもなく、IP直接（プロトコル番号89）
Helloパケット間隔 10秒 P-to-PとBroadcast（デフォルト）
Helloパケット間隔（NBMA） 30秒 Non-Broadcast Multi-Access（Frame Relay等）
Dead interval Hello×4 デフォルト40秒（P-to-P、Broadcast）
マルチキャストアドレス 224.0.0.5 全OSPFルータ宛
マルチキャストアドレス 224.0.0.6 DR/BDR宛

🤝OSPFネイバー確立の流れ

ネイバー確立の条件（一致しないとネイバーにならない！）

  • 同じArea ID
  • 同じHelloおよびDeadインターバル
  • 同じサブネット（IPアドレスの範囲）
  • 同じ認証情報（設定している場合）
  • スタブエリア設定の一致
  • MTUサイズの一致（DBD交換時）

OSPFネイバー状態遷移（7ステップ）

Down → Init → 2-Way → ExStart → Exchange → Loading → Full

① Down:     まだHelloを受信していない
② Init:     Helloを受信したが、Helloに自分のRouter IDが含まれていない
③ 2-Way:    双方のHelloに相手のRouter IDが含まれる（DR/BDR選出はここで実施）
④ ExStart:  DBDを使って主従関係（Master/Slave）を決定
⑤ Exchange: DBD（Database Description）を交換してLSDBの概要をやりとり
⑥ Loading:  LSRでLSAを要求し、LSUで受信 → LSAckで確認
⑦ Full:     LSDBが同期完了（ネイバー関係確立！）

⚖️OSPFのコスト計算

コスト = 参照帯域幅（デフォルト100Mbps）÷ インタフェース帯域幅

例:
  10Mbps Ethernet: 100,000,000 ÷ 10,000,000 = 10
  100Mbps FastEthernet: 100,000,000 ÷ 100,000,000 = 1
  1Gbps GigabitEthernet: 100,000,000 ÷ 1,000,000,000 = 0.1 → 切り上げて 1
  10Gbps: 100,000,000 ÷ 10,000,000,000 = 0.01 → 切り上げて 1

問題: 1Gbps以上は全て同じコスト（1）になってしまう！
解決: auto-cost reference-bandwidth で参照帯域幅を変更する

参照帯域幅を10000（10Gbps）に変更:
  100Mbps: 10,000 ÷ 100 = 100
  1Gbps:   10,000 ÷ 1000 = 10
  10Gbps:  10,000 ÷ 10000 = 1

🏆DR・BDRの選出（ブロードキャストネットワーク）

マルチアクセスネットワーク（Ethernet）では、全ルータがフルメッシュでLSAを交換するとトラフィックが爆発的に増えるため、代表ルータ（DR）の選出でこれを解決します。

役割 説明 フルアジャセンシー対象
DR（Designated Router） LSAを収集・配信する代表。224.0.0.6宛に送信 全OSPF ROUTERとフル
BDR（Backup DR） DRのバックアップ。DRが障害時に昇格 全OSPF ROUTERとフル
DROther DRでもBDRでもないルータ DR/BDRとのみフル（他のDROtherは2-Way止まり）

DR/BDR選出の優先順位

① OSPFプライオリティが最大のルータ（デフォルト1。0を設定するとDR/BDR選出に参加しない）
② プライオリティが同じ場合 → Router IDが最大のルータ
   Router IDの決定順: ① loopback IFの最大IP → ② 物理IFの最大IP → ③ router-id コマンドで手動設定

※ DR/BDR選出は一度決まると変わらない（先制なし）。DRが障害でBDRが昇格した後、
  元のDRが復帰してもDRには戻れない。

⚙️OSPF設定コマンド（完全版）

# OSPFプロセスを有効化（プロセスIDはローカルのみ有効。異なっても問題なし）
Router(config)# router ospf 1

# Router IDを手動設定（ベストプラクティス）
Router(config-router)# router-id 1.1.1.1

# networkコマンドでOSPFを有効にするインタフェースを指定
# 書式: network [IPアドレス] [ワイルドカードマスク] area [エリアID]
Router(config-router)# network 192.168.1.0 0.0.0.255 area 0
Router(config-router)# network 10.0.0.0 0.255.255.255 area 0

# インタフェースで直接OSPF有効化（現代の推奨方法）
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip ospf 1 area 0

# パッシブインタフェース（Hello送出を止める：エンドデバイス側の設定）
Router(config-router)# passive-interface GigabitEthernet0/0

# デフォルトルートをOSPFでアドバタイズ（インターネット接続ルータ）
Router(config-router)# default-information originate

# 参照帯域幅の変更（全ルータで統一必須）
Router(config-router)# auto-cost reference-bandwidth 10000    # 10Gbps基準

# インタフェースコストの手動設定
Router(config-if)# ip ospf cost 10

# OSPFインタフェースのHello/Dead間隔変更（両端一致必須）
Router(config-if)# ip ospf hello-interval 5
Router(config-if)# ip ospf dead-interval 20

✏️ 確認問題（第3-3章）

Q1. OSPFのデフォルトのHelloインターバル（ブロードキャストネットワーク）はどれか？
正解：A（10秒）
ブロードキャストおよびP-to-PネットワークのデフォルトHelloインターバルは10秒、Dead intervalは40秒（Hello×4）です。NBMA（Frame Relay等）はHello=30秒、Dead=120秒です。
Q2. OSPFのネイバーが Full 状態にならず 2-Way 状態で止まっている場合、最も考えられる原因はどれか？
正解：C（DROther同士は2-Way止まりが正常）
ブロードキャストネットワークでは、DRでもBDRでもないルータ（DROther）同士は2-Way状態が正常です。FullアジャセンシーはDR/BDRとDROther間のみ形成されます。これは正常な動作であり障害ではありません。
Q3. OSPFでRouter IDが決定される順序として正しいのはどれか？
正解：B
Router IDの優先順位: ①router-idコマンドで手動設定（最優先）→ ②loopbackインタフェースの最大IP → ③物理インタフェースの最大IP。router-idコマンドで設定するのがベストプラクティスです。
Q4. OSPFのコストはどのように計算されるか（デフォルト参照帯域幅の場合）？
正解：D
OSPFコスト = 100,000,000（参照BW）÷ インタフェース帯域幅（bps）。100Mbps FE=コスト1、10Mbps=コスト10。1Gbps以上は全てコスト1になる問題をauto-cost reference-bandwidthで解決します。
Q5. OSPFで「passive-interface」を設定するとどうなるか？
正解：A
passive-interfaceを設定するとHelloパケットの送信が止まりネイバーが確立しなくなります。ただしそのインタフェースのネットワークは引き続きOSPFでアドバタイズされます（ルートは残る）。エンドデバイスを接続するインタフェースに設定して不要なHelloを止めるのが用途です。

3-4 FHRP（HSRP・VRRP・GLBP）

頻出 デフォルトゲートウェイの冗長化プロトコルをマスターする

🔄FHRPとは

FHRP（First Hop Redundancy Protocol）はデフォルトゲートウェイの冗長化を実現するプロトコルの総称です。複数のルータが仮想IPアドレスを共有し、アクティブルータが障害時にスタンバイルータが自動引き継ぎをします。

🏆3つのFHRP比較

比較項目 HSRP VRRP GLBP
規格 Cisco独自 IEEE（標準） Cisco独自
アクティブ機器の呼称 Active Master AVG（Active Virtual Gateway）
バックアップ機器の呼称 Standby Backup AVF（Active Virtual Forwarder）
ロードバランシング なし（片方のみアクティブ） なし あり（複数ルータで分散）
仮想MACアドレス 0000.0C07.ACxx（xx=グループ番号） 0000.5E00.01xx（xx=VRID） 0007.B400.xxyy
Helloインターバル 3秒（デフォルト） 1秒（デフォルト） 3秒（デフォルト）
Hold time 10秒 3秒×複数 10秒

🛡️HSRP（Hot Standby Router Protocol）詳細

CCNAで最もよく出題されるFHRPです。2バージョンあります（HSRPv1とv2）。

HSRPの動作

              [PC群]
                |
        仮想IP: 192.168.1.254
        ┌───────────────────────┐
        │                       │
   [ルータR1]              [ルータR2]
   192.168.1.1             192.168.1.2
   HSRP Priority=110       HSRP Priority=100（デフォルト）
   状態: Active             状態: Standby
   仮想MACで応答            アクティブを監視（Helloで）

障害発生:
   R1がダウン → R2が10秒後にActive に昇格
   → 仮想IP・仮想MACをR2が引き継ぐ
   → PCのデフォルトゲートウェイ設定変更不要！

HSRPの設定コマンド

# R1（Activeにしたいルータ）の設定
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# standby 1 ip 192.168.1.254        # グループ1の仮想IP
R1(config-if)# standby 1 priority 110             # デフォルト100より高く設定
R1(config-if)# standby 1 preempt                  # 復帰時に再びActiveに（プリエンプト）
R1(config-if)# standby version 2                  # HSRPv2を使用（推奨）

# R2（Standbyルータ）の設定
R2(config-if)# ip address 192.168.1.2 255.255.255.0
R2(config-if)# standby 1 ip 192.168.1.254        # 同じ仮想IP
R2(config-if)# standby 1 priority 100             # デフォルト（Standbyになる）

# HSRPの確認コマンド
Router# show standby
Router# show standby brief
GigabitEthernet0/0 - Group 1
  State is Active  ←現在の状態
    Virtual IP address is 192.168.1.254
    Active virtual MAC address is 0000.0c07.ac01
    Local virtual MAC address is 0000.0c07.ac01 (v1 default)
  Priority 110 (configured 110)
  Preemption enabled
  Active router is local
🚨 Preempt（プリエンプト）を忘れずに設定
Preemptを設定しないと、Activeルータが復帰しても元のStandbyが継続してActiveのままになります。Preemptにより、優先度が高いルータが復帰した際に自動でActiveを取り返します。

✏️ 確認問題（第3-4章）

Q1. HSRPのデフォルトのPriorityはどれか？
正解：A（100）
HSRPのデフォルトPriorityは100です。Activeにしたいルータのみ110等の高い値を設定します。Priorityが同じ場合はIPアドレスが高い方がActiveになります。
Q2. FHRPの中でロードバランシング（複数ルータへの分散）に対応しているのはどれか？
正解：C（GLBP）
GLBPはAVGが仮想IP・複数のAVFが個別の仮想MACを持ち、クライアントを複数ルータに振り分けてロードバランシングができます。HSRPとVRRPは一度に1台しかActiveになれません。
Q3. HSRPでPreemptを設定する理由はどれか？
正解：B
Preemptなしでは、障害から復帰した高優先度ルータがStandbyに留まり、低優先度ルータが継続してActiveになります。Preemptを「standby 1 preempt」で設定すると、高優先度ルータが復帰時に自動でActiveを奪い返します。
Q4. VRRPの用語で「Masterルータ」に相当するHSRPの用語はどれか？
正解：D（Active）
HSRPのActive = VRRPのMaster（代表として仮想IPに応答するルータ）。HSRPのStandby = VRRPのBackup（待機中のルータ）。
