📐OSI参照モデルとは

OSI（Open Systems Interconnection）参照モデルはISO（国際標準化機構）が策定したネットワーク通信を7つの層に分けた概念的な標準です。実際の通信プロトコルの設計・理解・トラブルシューティングの共通言語として使われます。

OSI 7層モデル（完全版）

層番号  層名              英語名                PDU            主な役割・プロトコル
────────────────────────────────────────────────────────────────────────────
L7      アプリケーション層  Application Layer   データ（Data） HTTP/S、FTP、DNS、SMTP、Telnet、SSH
L6      プレゼンテーション層 Presentation Layer  データ（Data） 文字コード変換、暗号化/復号、圧縮
L5      セッション層       Session Layer        データ（Data） セッション確立・維持・終了管理
L4      トランスポート層   Transport Layer      セグメント     TCP、UDP　ポート番号で多重化
L3      ネットワーク層     Network Layer        パケット       IP（v4/v6）、ICMP、ルーティング
L2      データリンク層     Data Link Layer      フレーム       Ethernet、Wi-Fi、VLAN（802.1Q）、ARP
L1      物理層            Physical Layer        ビット         ケーブル、コネクタ、電気/光信号
💡 OSI層の暗記法（上から）
「All People Seem To Need Data Processing」
Application / Presentation / Session / Transport / Network / Data Link / Physical

各層の詳細説明

層 機能の詳細 主なプロトコル・規格 Ciscoコマンドとの関係
L7
アプリケーション		 エンドユーザーが直接使うサービスを提供。Webブラウザ・メール・FTPクライアントなど HTTP(80)、HTTPS(443)、FTP(21)、SMTP(25)、DNS(53)、DHCP(67/68)、Telnet(23)、SSH(22) ACLでポート番号によるフィルタリング
L6
プレゼンテーション		 データの表現形式を変換：文字コード（ASCII/Unicode）変換、SSL/TLS暗号化・復号、データ圧縮 SSL/TLS、JPEG、MPEG、ASCII、UTF-8 HTTPS通信のSSLオフロード
L5
セッション		 通信セッションの確立・維持・終了を管理。NFS・RPC等の複数接続管理 NFS、RPC、NetBIOS —
L4
トランスポート		 エンドツーエンドの通信制御。ポート番号で複数アプリを多重化。TCPは信頼性、UDPは高速性 TCP（信頼性・順序保証）、UDP（高速・低遅延） 拡張ACLのポート番号指定（eq 80等）
L3
ネットワーク		 異なるネットワーク間の論理アドレス（IP）による転送。ルーティング・パスの選択 IPv4、IPv6、ICMP、OSPF、BGP ip route、show ip route、router ospf
L2
データリンク		 同一ネットワーク内の隣接機器間の転送。MACアドレスで識別。エラーチェック（FCS） Ethernet、IEEE 802.11（Wi-Fi）、PPP、HDLC、Frame Relay show mac address-table、switchport
L1

🔄データのカプセル化と非カプセル化

送信側では各層がヘッダ（/フッタ）を追加しながら下の層へ渡します（カプセル化）。受信側では逆に各層がヘッダを取り除きながら上の層へ渡します（非カプセル化）。

カプセル化の流れ（送信側）

L7/L6/L5  アプリケーション   [データ]
              ↓ L4ヘッダ追加（ポート番号・シーケンス番号）
L4        トランスポート     [TCPヘッダ | データ]  ← セグメント
              ↓ L3ヘッダ追加（送信元IP・宛先IP）
L3        ネットワーク       [IPヘッダ | TCPヘッダ | データ]  ← パケット
              ↓ L2ヘッダ+フッタ追加（送信元MAC・宛先MAC・FCS）
L2        データリンク       [L2ヘッダ | IPヘッダ | TCPヘッダ | データ | FCS]  ← フレーム
              ↓ ビット変換
L1        物理              1010100111011...  ← ビット（信号）
🚨 PDU（Protocol Data Unit）の名称は必須暗記
L4=セグメント（TCP）/ データグラム（UDP）、L3=パケット、L2=フレーム、L1=ビット

🖥️TCP/IPモデル（実際のインターネットで使われるモデル）

TCP/IPモデルはOSIより先に実用化された4層モデルです。インターネットの実際の実装はTCP/IPモデルに従っています。

TCP/IP層 対応するOSI層 主なプロトコル
アプリケーション層 L5 + L6 + L7 HTTP/S、FTP、DNS、DHCP、SMTP、Telnet、SSH、SNMP
トランスポート層 L4 TCP、UDP
インターネット層 L3 IP（v4/v6）、ICMP、ARP（直接的には）
ネットワークアクセス層 L1 + L2 Ethernet、Wi-Fi、PPP、光ファイバー

📬ARPの動作（L2とL3の橋渡し）

ARP（Address Resolution Protocol）は宛先IPアドレスから宛先MACアドレスを解決するプロトコルです。L3とL2の橋渡しをします。

ARPの動作手順

① PC-Aが 192.168.1.20 に通信したいが MACアドレスが不明
② PC-A → ブロードキャスト ARP Request:
   「192.168.1.20 のMACアドレスを教えてください」（宛先MAC: FF:FF:FF:FF:FF:FF）
③ PC-B（192.168.1.20）→ ユニキャスト ARP Reply:
   「私のMACアドレスは AA:BB:CC:DD:EE:FF です」
④ PC-AはARPキャッシュにIPとMACの対応を登録
⑤ 以降は ARPキャッシュを参照してフレームを送信

確認: arp -a（Windowsコマンド）でARPキャッシュを確認できます。

🔍トラブルシューティングとOSI層

障害対応ではボトムアップ（L1→L7）またはトップダウン（L7→L1）でOSI層を確認します。

確認コマンド 対象OSI層 確認内容
show interfaces L1 / L2 リンク状態（up/down）、エラーカウンタ
show ip interface brief L3 IPアドレス・インタフェース状態
show ip route L3 ルーティングテーブル
ping L3（ICMP） L3到達性確認
telnet / ssh L4〜L7 L4〜L7到達性確認

✏️ 確認問題（第1-2章）

Q1. OSI参照モデルでMACアドレスを使って隣接する機器へデータを転送するのはどの層か？
正解：B（データリンク層 L2）
L2はMACアドレスを使い同一リンク（ネットワーク）内の隣接機器間でフレームを転送します。IPアドレスを使うのはL3のネットワーク層です。
Q2. TCPとHTTPで通信するWebブラウジングのとき、L4のPDU名称はどれか？
正解：C（セグメント）
PDU名称：L4(TCP)=セグメント、L4(UDP)=データグラム、L3=パケット、L2=フレーム、L1=ビット。これはCCNA頻出の暗記事項です。
Q3. カプセル化の説明として正しいものはどれか？
正解：A
送信側でL7→L1へデータが渡される際、各層がヘッダ（L2はフッタも）を追加します。受信側（L1→L7）では逆に各層がヘッダを除去します（非カプセル化・デカプセル化）。
Q4. TCP/IPモデルの「インターネット層」に対応するOSI層はどれか？
正解：D（L3 ネットワーク層）
TCP/IPの4層とOSI対応：アプリケーション=L5〜L7、トランスポート=L4、インターネット=L3、ネットワークアクセス=L1〜L2。
Q5. ARPプロトコルの目的として正しいのはどれか？
正解：A（IPアドレス→MACアドレス）
ARPはメッセージを送る前に宛先MACアドレスが必要なときに使用します。ARPリクエストはブロードキャスト（FF:FF:FF:FF:FF:FF）で送り、対象ホストがユニキャストでMACアドレスを返します。逆方向（MACアドレス→IP）はRARPです。DNSはドメイン名→IP解決です。
Q6. SSL/TLSによる暗号化・復号はOSI参照モデルのどの層の機能か？
正解：C（プレゼンテーション層 L6）
L6プレゼンテーション層はデータ表現の変換（文字コード、暗号化/復号、圧縮）を担います。SSL/TLSはHTTPS通信で使われる暗号化プロトコルです。
Q7. ネットワーク障害をボトムアップで確認する場合、最初に確認するOSI層はどれか？
正解：B（L1 物理層）
ボトムアップアプローチはL1（物理：ケーブル接続確認）→L2（リンクアップ確認）→L3（IP・ルーティング確認）→L4→L7の順に上位へ確認します。トップダウンは逆です。
