2-6 無線LAN（WLC・AP）

頻出概念設定 エンタープライズ無線LANの設計・管理・トラブルシューティングを体系的に理解する

🏗️エンタープライズ無線LAN設計

3層アーキテクチャモデル

  [WLC（Wireless LAN Controller）]
    ├── 集中管理: 全APの設定・ポリシーを一元管理
    ├── ファームウェア管理: 全APのIOSを自動更新
    ├── セキュリティポリシー: WLAN/SSID/認証を一括適用
    └── RF管理: チャネル・出力の自動最適化（RRM）

         │ CAPWAP Tunnel
         │ (UDP/5246制御, UDP/5247データ)
         ▼
  [Lightweight AP × 多数]
    ├── 複雑な処理はWLCに任せる（Thin AP）
    ├── 「知性」はWLCに集約、APは安価で交換容易
    └── WLC障害時の動作はモードに依存

Split MACアーキテクチャ:
  MAC層の処理を「AP側」と「WLC側」に分担
  ┌─────────────────────────────┐
  │ APが処理:                         │
  │  ・ビーコン送信                     │
  │  ・プローブ応答                     │
  │  ・暗号化/復号（データフレーム）      │
  │  ・802.11フレームの送受信            │
  ├─────────────────────────────┤
  │ WLCが処理:                         │
  │  ・認証（802.1X / PSK）              │
  │  ・セキュリティポリシー適用           │
  │  ・QoSポリシー                      │
  │  ・ローミング管理                    │
  │  ・RF管理（チャネル・出力自動調整）     │
  └─────────────────────────────┘

APの動作モード（CCNA必須！）

モード データ転送 用途
Localモード 全データをCAPWAPトンネル経由でWLCへ転送 通常運用（本社等、WLCが近い環境）
FlexConnectモード ローカルスイッチング可能。WAN障害時もクライアント間通信継続 リモート拠点（支店）向け
Monitorモード データ転送しない 不正AP検出・IDS/IPS専用
Snifferモード データ転送しない パケットキャプチャ（分析ツールにミラー）
Bridgeモード ポイントツーポイント 建物間の無線ブリッジ

📡ローミング

クライアントがAP間を移動する時の挙動

┌────────┐          ┌────────┐
│  AP-1   │ ←移動→  │  AP-2   │
│ CH: 1   │          │ CH: 6   │
└────┬───┘          └────┬───┘
     │  CAPWAP              │  CAPWAP
     └──────┬───────┘
             │
        ┌────┴────┐
        │    WLC     │
        └──────────┘

L2ローミング（同一VLAN内）:
  ・シームレスに移動可能
  ・IPアドレスは変わらない
  ・WLCが新APにクライアント情報を引き継ぎ

L3ローミング（異なるVLAN/サブネット間）:
  ・アンカーWLCの仕組みで元のIPアドレスを維持
  ・より複雑な処理が必要

# ① Webブラウザ（HTTPS）── メインの管理方法
# ② SSH/Telnet（CLI）
# ③ Cisco DNA Center（APIベース）

# WLC GUIでの主な設定項目

# ・AP管理（モード変更・チャネル割り当て）
# ・クライアント監視・トラブルシューティング

# AP-WLC間の初期接続（APのディスカバリ）
# APがWLCを見つける方法（優先順位順）:
# 1. 以前接続したWLCのIP（NVRAM保存）
# 2. DHCPオプション43（ベンダー固有情報でWLCのIPを通知）
# 3. DNS解決（CISCO-CAPWAP-CONTROLLER.localdomain）
# 4. ブロードキャスト（同一サブネットのWLCを探索）
💡 DHCPオプション43
リモート拠点のAPがWLCを自動的に見つけるために最もよく使われる方法です。DHCPサーバーのオプション43にWLCのIPアドレスを設定しておくと、APがIPアドレス取得時に一緒にWLCの場所を知ることができます。

✏️ 確認問題（第2-6章）

Q1. Split MACアーキテクチャでWLC側が処理するものはどれか？
正解：B
Split MACではリアルタイム無線処理（ビーコン・プローブ応答・暗号化）はAPが処理し、管理機能（認証・ポリシー・QoS・RF管理・ローミング）はWLCが処理します。
Q2. リモート拠点のLightweight APがWLCを自動的に発見するために最もよく使われる方法はどれか？
正解：A
DHCPオプション43は異なるサブネットのAPがWLCを見つける最も一般的な方法です。ブロードキャストは同一サブネットでのみ有効です。
Q3. CAPWAPの制御チャネルとデータチャネルについて正しいのはどれか？
正解：D
CAPWAP制御トンネル=UDP/5246(DTLS暗号化は必須)。データトンネル=UDP/5247(暗号化はオプション)。Bはポート番号が逆です。
Q4. 不正APの検出を目的としたAPモードはどれか？
正解：C（Monitor）
Monitorモードはクライアントにサービスを提供せず、不正AP検出やセキュリティ監視に特化したモードです。FlexConnect=リモート拠点。Local=通常運用。Bridge=建物間接続。
