1-4 IPv6アドレス

頻出 IPv6のアドレス種別・省略ルール・EUI-64をマスターする

🌐なぜIPv6が必要か

IPv4のアドレスは32ビット（約43億個）しかなく、インターネットの爆発的な普及により2011年にIANAのIPv4アドレスプールが枯渇しました。IPv6は128ビット（約340澗=3.4×10³⁸個）のアドレス空間を持ち、NATなしで全デバイスにグローバルIPを割り当てられます。

比較項目 IPv4 IPv6
アドレス長 32ビット 128ビット
表記 10進ドット区切り 192.168.1.1 16進コロン区切り 2001:db8::1
アドレス空間 約43億 約3.4×10³⁸
ブロードキャスト あり なし（マルチキャストで代替）
ARP ARP（ブロードキャスト） NDP/ICMPv6 Neighbor Solicitation
ヘッダ 可変長（20〜60B） 固定40B（シンプル化）
設定 手動またはDHCP SLAAC（ステートレス自動設定）可
フラグメント 中間ルータも可能 送信元ホストのみ
QoS ToSフィールド フローラベル（20bit）で改善

✍️IPv6アドレスの表記ルール

128ビットを16ビット（4桁16進数）ごとにコロンで区切り、8グループで表します。

2つの省略ルール

【完全形】
2001:0db8:0000:0000:0000:0000:0000:0001

【ルール1】各グループの先頭0を省略
2001:db8:0:0:0:0:0:1

【ルール2】連続する全0グループを「::」で一か所だけ省略
2001:db8::1

⚠️ 「::」は1か所だけ使用可能（2か所以上使うとどこが0かわからなくなる）

よくある例:
::1             ← ループバックアドレス（127.0.0.1 相当）を省略
::              ← 全ゼロ（0:0:0:0:0:0:0:0）を省略
fe80::1         ← リンクローカル（FE80:0:0:0:0:0:0:1 を省略）

🏷️IPv6アドレスの種別（試験必須）

種別 プレフィックス 特徴・用途 IPv4の相当
グローバルユニキャスト 2000::/3（2xxx〜3xxx） インターネット上でグローバルに一意 パブリックIPアドレス
リンクローカル FE80::/10 同一リンク内のみ有効。自動生成される。OSPFv3等のL3プロトコルに必須 169.254.0.0/16（APIPA）
ユニークローカル FC00::/7（FC〜FD） 組織内プライベートアドレス。外部へルーティング不可 プライベートIPアドレス
マルチキャスト FF00::/8 複数宛先へ同時配信。ブロードキャストの代替 224.0.0.0/4（クラスD）
エニーキャスト ユニキャストと同じ範囲 最も近いノードへ1対1転送。DNSルートサーバー等で使用 —
ループバック ::1/128 自分自身（テスト用） 127.0.0.1
不特定（全ゼロ） ::/128 未設定状態やソースアドレス不明を示す 0.0.0.0

重要なマルチキャストアドレス暗記リスト

マルチキャストアドレス 対象
FF02::1 リンク上のすべてのノード（全IPv6ホスト）
FF02::2 リンク上のすべてのルータ
FF02::5 全OSPFv3ルータ（224.0.0.5の相当）
FF02::6 OSPFv3 DR/BDR（224.0.0.6の相当）

🔧EUI-64によるインタフェースID自動生成

EUI-64の計算手順（3ステップ）

MACアドレス: AA:BB:CC:DD:EE:FF（48ビット）

【ステップ1】中央に FFFE を挿入して64ビット化
  AA:BB:CC : FF:FE : DD:EE:FF

【ステップ2】先頭バイト（AA）の第7ビット（U/Lビット）を反転
  AA  = 1010 1010
  第7ビット（左から7番目）を反転  →  1010 1000 = A8
  ※ AA（偶数MACなら0→1に反転）

【ステップ3】結合してインタフェースIDとする
  A8BB:CCFF:FEDD:EEFF

リンクローカルの完成形（FE80:: + EUI-64）:
  FE80::A8BB:CCFF:FEDD:EEFF/64
📌 U/Lビット反転の意味
EUI-64でMACの第7ビット（Universal/Localビット）を反転するのは、IEEEのMACアドレス管理上の"ユニバーサル管理"を示すビットを"ローカル管理"ビットとして使うIETFの慣習です。試験では「第7ビットを反転する」という事実を覚えれば十分です。

⚙️IPv6アドレスの割り当て方式

方式 説明
手動設定（静的） 管理者がコマンドでIPv6アドレスを設定
SLAAC ステートレスアドレス自動設定。ルータのRAメッセージからプレフィックスを取得し、EUI-64でアドレスを自動生成。DHCPv6サーバー不要
DHCPv6（ステートフル） DHCPv6サーバーからアドレス・DNSサーバー等を取得。アドレス管理が一元化できる
DHCPv6（ステートレス） アドレスはSLAACで生成、DNS等の情報はDHCPv6から取得

Cisco ルータでのIPv6設定

# IPv6ルーティングを有効化（必須！デフォルトは無効）
Router(config)# ipv6 unicast-routing

# インタフェースにIPv6アドレスを設定
Router(config-if)# ipv6 address 2001:db8:1::1/64

# EUI-64で自動生成（末尾に eui-64 を付ける）
Router(config-if)# ipv6 address 2001:db8:1::/64 eui-64

# リンクローカルを手動設定（推奨）
Router(config-if)# ipv6 address fe80::1 link-local

# 確認コマンド
Router# show ipv6 interface brief
Router# show ipv6 route

✏️ 確認問題（第1-4章）

Q1. IPv6のリンクローカルアドレスのプレフィックスはどれか？
正解：C（FE80::/10）
リンクローカルアドレスはFE80::/10のプレフィックスを持ち、同一リンク内のみ有効です。OSPFv3のネイバー確立など、L3プロトコルの動作に必須です。
Q2. EUI-64でインタフェースIDを生成する際、MACアドレスに挿入する値はどれか？
正解：B（FFFE）
EUI-64は48ビットのMACアドレスの中央（24ビット目と25ビット目の間）に「FFFE」を挿入して64ビットのインタフェースIDを生成します。さらに第7ビット（U/Lビット）を反転します。
Q3. IPv6でブロードキャストが廃止された代替として使用されるものはどれか？
正解：A（マルチキャスト）
IPv6ではブロードキャストが廃止され、マルチキャストで代替されます。例えば全ホスト宛=FF02::1、全ルータ宛=FF02::2です。
Q4. CiscoルータでIPv6ルーティングを有効にするコマンドはどれか？
正解：D（ipv6 unicast-routing）
Ciscoルータはデフォルトでは「ipv6 unicast-routing」が無効です。このコマンドをグローバルコンフィグモードで入力しないとIPv6パケットのルーティングが行われません。
Q5. SLAAC（ステートレスアドレス自動設定）の説明として正しいのはどれか？
正解：C
SLAACはDHCPv6サーバー不要でIPv6アドレスを自動設定します。ルータのRouter Advertisement（RA）メッセージからプレフィックスを取得し、それにEUI-64で生成したインタフェースIDを組み合わせてアドレスを生成します。

1-5 TCP・UDP・ポート番号

頻出 L4プロトコルの違いと主要ポート番号は完全暗記必須

🔄TCP（Transmission Control Protocol）

TCPはL4のコネクション型プロトコルで、信頼性の高いデータ転送を提供します。

TCPの主要機能

  • コネクション確立（3ウェイハンドシェイク）： データ転送前に接続を確立
  • シーケンス番号：データに番号を付けて順序を保証
  • 確認応答（ACK）：受信側が受け取りを確認。未受信分は再送
  • フロー制御：ウィンドウサイズで受信バッファの溢れを防ぐ
  • 輻輳制御：ネットワークの混雑を検知して送信レートを調整
  • コネクション終了（4ウェイFIN）：接続を正常に終了

TCPの3ウェイハンドシェイク

クライアント                    サーバー
    |                              |
    |─── SYN (SEQ=100) ──────────→|  ① 接続要求（SYN）
    |                              |
    |←── SYN-ACK (SEQ=200,ACK=101)|  ② 受入+確認（SYN+ACK）
    |                              |
    |─── ACK (ACK=201) ──────────→|  ③ 確認応答（ACK）
    |                              |
    |       ≪接続確立≫             |
    |─── データ ─────────────────→|

SYN=Synchronize（同期）、ACK=Acknowledgment（確認応答）

⚡UDP（User Datagram Protocol）

UDPはL4のコネクションレス型プロトコルで、確認応答や再送がない代わりに低遅延でシンプルな転送を行います。

比較項目 TCP UDP
接続方式 コネクション型（3ウェイHS） コネクションレス型
信頼性 高い（再送・順序保証） 低い（再送なし・順序保証なし）
速度 遅い（ヘッダ・制御処理あり） 速い（オーバーヘッド少ない）
ヘッダサイズ 20〜60バイト 8バイト（固定）
フロー制御 あり（ウィンドウサイズ） なし
輻輳制御 あり なし
主な用途 HTTP/S、FTP、SSH、SMTP、Telnet DNS、DHCP、SNMP、VoIP、動画配信、TFTP

✏️ 確認問題（第1-5章）

Q1. TCPの3ウェイハンドシェイクの順序として正しいのはどれか？
正解：B（SYN → SYN-ACK → ACK）
クライアントがSYNを送り→サーバーがSYN-ACKで応答→クライアントがACKを送って接続確立。「Synchronize → Synchronize-Acknowledge → Acknowledge」の頭文字SSA-SSA-ACKで覚えましょう。
Q2. リアルタイム音声通話（VoIP）に適したL4プロトコルはどれか？その理由も含めて正しい選択肢を選べ。
正解：A（UDP）
VoIPでは1パケット欠落しても再送を待つよりそのまま再生した方が通話品質が高い（遅延なし）ため、UDPが使われます。Dは誤り（UDPにパケット損失を自動修復する機能はない）。
Q3. DHCPサーバーが使用するポート番号として正しいのはどれか？
正解：C（UDP 67）
DHCPサーバーはUDPポート67で待機します。クライアントはUDPポート68から送信します（67=サーバー、68=クライアント）。DHCPはコネクションなしのブロードキャストを使うためUDPです。
Q4. SSHのポート番号はどれか？
正解：D（22）
SSH=22（暗号化リモートアクセス）、Telnet=23（平文）、FTP-control=21、HTTP=80。CCNAではSSH（22）とTelnet（23）の違いは特に重要です。
Q5. SNMPポーリング（Get/Set）で使用されるポート番号はどれか？
正解：B（UDP 161）
SNMP Get/Set=UDP 161（マネージャー→エージェントへの要求）、SNMP Trap=UDP 162（エージェント→マネージャーへの自発的通知）。どちらもUDPです。
