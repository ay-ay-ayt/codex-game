6-1 ネットワーク自動化（SDN・コントローラ）

頻出概念 従来型ネットワークとSDNの違い、コントローラの役割を理解する

🔄従来のネットワーク管理の問題点

「CLIで1台ずつ設定」の限界

【従来型ネットワーク管理】
管理者がSSHで各機器に1台ずつログインして設定
    例: 100台のスイッチのVLAN設定を変更
    → SSHで100回ログイン → 同じコマンドを100回入力
    → 1台でもタイプミスがあると障害発生
    → 設定の整合性を確認するのに膨大な時間

問題点:
① スケーラビリティ: 100台、1000台になると人力で対応不能
② ヒューマンエラー: 手動作業ではミスが避けられない
③ 一貫性: 設定のバラつき → 障害、セキュリティホール
④ 応答速度: ビジネス要求に対する変更が遅い

🏗️SDN（Software-Defined Networking）

SDNはネットワークの制御をソフトウェア（コントローラ）に集中させるアーキテクチャです。

従来型 vs SDNの構造比較

【従来型ネットワーク】
各機器がそれぞれ制御プレーンとデータプレーンを持つ

  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ 制御プレーン│  │ 制御プレーン│  │ 制御プレーン│
  │(経路計算等) │  │(経路計算等) │  │(経路計算等) │
  ├──────────┤  ├──────────┤  ├──────────┤
  │ データプレーン│  │データプレーン│  │データプレーン│
  │(パケット転送) │  │(パケット転送)│  │(パケット転送)│
  └──────────┘  └──────────┘  └──────────┘
     Router A        Router B        Router C

【SDNアーキテクチャ】
制御プレーンをSDNコントローラに集約

  ┌──────────────────────────────────────┐
  │         SDNコントローラ（制御プレーン）          │
  │   経路計算・ポリシー管理・ネットワーク全体把握     │
  │   ↕ Southbound API（OpenFlow等）                │
  └──────────────────────────────────────┘
        ↕                ↕                ↕
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │データプレーン│  │データプレーン│  │データプレーン│
  │(パケット転送) │  │(パケット転送)│  │(パケット転送)│
  └──────────┘  └──────────┘  └──────────┘
     Switch A        Switch B        Switch C

ネットワークの3つのプレーン

プレーン 役割 具体例
データプレーン（転送プレーン） 実際のパケットの転送・フィルタリング フレーム転送、ACLの適用、NATの変換、QoSのマーキング
制御プレーン 転送先の決定（ルーティングテーブルの作成） OSPF、STP、ARP処理
管理プレーン 機器の設定・監視 SSH、SNMP、Syslog、NTP

SDNのAPIインタフェース

API種類 方向 用途 例
Northbound API コントローラ ← アプリケーション アプリケーションがコントローラに指示を出す REST API
Southbound API コントローラ → ネットワーク機器 コントローラが機器を制御する OpenFlow, NETCONF, RESTCONF
💡 覚え方: North = 上（アプリ側）、South = 下（機器側）
「アプリ → [Northbound] → コントローラ → [Southbound] → 機器」の順に指示が流れます。

Cisco DNA Center

Cisco DNA Centerは企業向けのSDNコントローラです。

  • Intent-Based Networking（IBN）: 管理者が「意図」（例:「ゲストユーザーはWebのみアクセス可」）を伝えると、コントローラが自動で設定を生成・適用
  • Assurance: ネットワーク全体の状態を可視化し、問題を自動検知・推奨対策を提示
  • GUI/APIベース: CLIではなくWebブラウザやAPIで全て管理

✏️ 確認問題（第6-1章）

Q1. SDNで、アプリケーションがSDNコントローラに指示を出すために使用するAPIはどれか？
正解：B（Northbound API）
Northbound APIはコントローラの「上側」のインタフェースで、アプリケーションやスクリプトからコントローラに指示を出します。通常REST APIで実装されます。Southbound APIはコントローラから「下側」のネットワーク機器を制御するインタフェースです。
Q2. SDNの最大の利点として正しいのはどれか？
正解：A
SDNの本質的な利点は制御プレーンの集中化による一元管理・自動化です。API経由でプログラマブルに制御でき、大規模ネットワークの設定・管理の効率が飛躍的に向上します。
Q3. ネットワーク機器のパケット転送処理が行われるプレーンはどれか？
正解：C（データプレーン）
データプレーン=パケットの実際の転送・フィルタリング処理。制御プレーン=OSPF等の経路計算・ルーティングテーブル作成。管理プレーン=SSH/SNMP等の設定・監視です。

6-2 REST API・JSON・自動化ツール

頻出概念 REST API・データ形式（JSON/YAML/XML）・構成管理ツールを理解する

🌐REST API ── ネットワーク機器のプログラマブル制御

REST API（REpresentational State Transfer）は、HTTPメソッドを使ってネットワーク機器やコントローラにリクエストを送り、設定変更やデータ取得を行う方法です。

HTTPメソッドとCRUD操作の対応（必須暗記！）

HTTPメソッド CRUD 説明 REST API例
GET Read データの取得（変更なし） GET /api/v1/interfaces → インタフェース一覧取得
POST Create 新しいリソースの作成 POST /api/v1/vlans → 新しいVLAN作成
PUT Update（全体置換） 既存リソースの完全更新 PUT /api/v1/vlans/10 → VLAN 10を全属性更新
PATCH Update（部分更新） 既存リソースの一部を更新 PATCH /api/v1/vlans/10 → VLAN 10の名前だけ変更
DELETE Delete リソースの削除 DELETE /api/v1/vlans/10 → VLAN 10を削除

HTTPレスポンスコード

コード 意味 具体例
200 OK 成功 GET/PUT/DELETEが正常完了
201 Created リソース作成成功 POST成功（新しいVLAN作成等）
400 Bad Request リクエスト不正 JSONの構文エラー等
401 Unauthorized 認証エラー APIキー/トークンが無効
403 Forbidden 権限不足 認証成功だが操作権限なし
404 Not Found リソースが見つからない 存在しないURLへのリクエスト
500 Internal Server Error サーバー側のエラー サーバーの内部処理でエラー発生

📄データ形式: JSON・YAML・XML

API通信では構造化されたデータ形式を使います。CCNAでは3つの形式を区別できる必要があります。

JSON（JavaScript Object Notation）── 最も広く使われる

{
  "interface": {
    "name": "GigabitEthernet0/1",
    "ip_address": "192.168.1.1",
    "subnet_mask": "255.255.255.0",
    "status": "up",
    "vlans": [10, 20, 30]
  }
}

特徴:
・キーと値のペア（"key": "value"）
・波括弧 { } でオブジェクト、角括弧 [ ] で配列
・文字列は必ずダブルクォーテーション
・コメントは使えない

YAML（YAML Ain't Markup Language）── 人間に読みやすい

interface:
  name: GigabitEthernet0/1
  ip_address: 192.168.1.1
  subnet_mask: 255.255.255.0
  status: up
  vlans:
    - 10
    - 20
    - 30

特徴:
・インデントで構造を表現（スペース使用、タブ不可！）
・クォーテーション不要の場合が多い
・コメント可（# コメント）
・Ansible等の構成管理ツールで人気

XML（eXtensible Markup Language）── タグベース

<interface>
  <name>GigabitEthernet0/1</name>
  <ip_address>192.168.1.1</ip_address>
  <subnet_mask>255.255.255.0</subnet_mask>
  <status>up</status>
  <vlans>
    <vlan>10</vlan>
    <vlan>20</vlan>
    <vlan>30</vlan>
  </vlans>
</interface>

特徴:
・開始タグ <tag> と終了タグ </tag> で囲む
・冗長だが厳密な構造定義が可能
・NETCONFプロトコルで使用

🛠️構成管理ツール

ツール 方式 エージェント 設定記述 通信
Ansible プッシュ型 不要（エージェントレス） YAML（Playbook） SSH
Puppet プル型 必要 独自DSL（Manifest） HTTPS/8140
Chef プル型 必要 Ruby（Recipe） HTTPS
🚨 Ansibleが特に重要（CCNA頻出）
  • エージェントレス: 対象機器にソフトウェアのインストールが不要（SSH接続のみ）
  • Playbook: YAML形式で設定手順を定義
  • 冪等性（べきとうせい）: 同じPlaybookを何度実行しても同じ結果（=安全に繰り返し実行可能）
  • Inventory: 管理対象のホスト一覧を定義するファイル

NETCONF・RESTCONF

プロトコル トランスポート データ形式 操作
NETCONF SSH（TCP/830） XML get, get-config, edit-config, copy-config, delete-config, lock/unlock
RESTCONF HTTPS JSON or XML GET, POST, PUT, PATCH, DELETE（REST風）

✏️ 確認問題（第6-2章）

Q1. REST APIで新しいリソースを作成するために使用するHTTPメソッドはどれか？
正解：C（POST）
POST=Create（作成）、GET=Read（読取）、PUT=Update全体（更新）、PATCH=Update部分（部分更新）、DELETE=Delete（削除）。CRUD操作とHTTPメソッドの対応は必須知識です。
Q2. 以下のデータ形式を見て、これが何形式か特定せよ。
{ "hostname": "R1", "interfaces": [{"name": "Gi0/0", "ip": "10.0.0.1"}] }
正解：A（JSON）
波括弧{} でオブジェクト、角括弧[]で配列、ダブルクォーテーションで囲まれたキーと値のペアはJSON形式の特徴です。YAMLはインデントベース（括弧不使用）、XMLはタグ<>ベースです。
Q3. Ansibleの特徴として正しいのはどれか？
正解：D
Ansibleの3大特徴: ①エージェントレス（対象機器にソフト不要、SSHのみ）②YAML形式のPlaybook ③プッシュ型（管理サーバーから対象に設定を送信）。エージェント必要+プル型はPuppet/Chef、RubyはChefです。
Q4. HTTPレスポンスコード「401」が返ってきた場合、何を意味するか？
正解：B（認証エラー）
401 Unauthorized=認証情報が無効。400=リクエスト構文エラー。403=認証成功だが権限不足。404=リソースなし。500=サーバーエラー。
Q5. NETCONFプロトコルのトランスポートとデータ形式の正しい組み合わせはどれか？
正解：A
NETCONF=SSH(TCP/830)+XML。RESTCONF=HTTPS+JSON/XML。NETCONFはSSHトンネル上でXMLメッセージをやり取りし、edit-config等の操作でネットワーク機器を設定します。
