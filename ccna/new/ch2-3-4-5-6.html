2-3 EtherChannel（ポートチャネル）

頻出設定 複数リンクを束ねて帯域拡大と冗長化を実現する技術

🔗EtherChannelとは

EtherChannelは複数の物理リンクを1本の論理リンクにまとめる技術です。帯域幅の拡大（最大8本のリンクを束ねる）と冗長性（1本障害でも通信継続）を同時に実現します。

EtherChannelの効果

【EtherChannelなし】         【EtherChannelあり】
スイッチA ─ 1Gbps ─ スイッチB   スイッチA ═══ 4Gbps ═══ スイッチB
           ─ 1Gbps ─            ← 4本の1Gbpsリンクを論理的に束ねる
           ─ 1Gbps ─             → 見かけ上は1本の4Gbpsリンク
           ─ 1Gbps ─            STPは1本の論理リンクとして認識
                                 → ブロックされない！
🚨 STPとEtherChannelの関係
EtherChannelなしで複数リンクをスイッチ間に接続するとSTPがループを防ぐためほとんどのポートをブロックします。EtherChannelを使うとSTPは論理的に1本のリンクとして認識するためブロックされず全帯域を使えます。

🔄EtherChannelの交渉プロトコル

プロトコル 規格 アクティブ側 パッシブ側 特徴
LACP IEEE 802.3ad（標準） active passive マルチベンダー対応。activeとpassiveの組み合わせでEtherChannel形成
PAgP Cisco専用 desirable auto Cisco機器同士のみ。desirableとautoの組み合わせでEtherChannel形成
静的（on） 交渉なし on on プロトコルなし。両端をonにする。片方がonで片方が違うと障害になるため非推奨
💡 passive + passive = NG！
LACP: active+active ○ active+passive ○ passive+passive ✗（両方が受動的なので形成されない）
PAgP: desirable+desirable ○ desirable+auto ○ auto+auto ✗（同上）

⚙️EtherChannel設定コマンド

# LACP（IEEE 802.3ad）で EtherChannel を設定（推奨）
Switch(config)# interface range GigabitEthernet0/1 - 4
Switch(config-if-range)# channel-group 1 mode active      # LACP アクティブ
Switch(config-if-range)# channel-protocol lacp                # 明示的に指定（任意）

# PAgP で EtherChannel を設定（Ciscoのみ）
Switch(config)# interface range GigabitEthernet0/1 - 4
Switch(config-if-range)# channel-group 1 mode desirable

# ポートチャネルインタフェースの設定（VLAN・Speed等）
Switch(config)# interface port-channel 1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 999

# EtherChannel確認コマンド
Switch# show etherchannel summary

EtherChannelを設定する際の注意点

  • 束ねるポートは速度・duplex・VLANモード（アクセス/トランク）・ネイティブVLANがすべて一致していること
  • 設定はポートチャネルインタフェースに行う（個別の物理ポートに設定しない）
  • 最大8本のアクティブポート（LACPは最大8本アクティブ+8本スタンバイ）

✏️ 確認問題（第2-3章）

Q1. EtherChannelをLACPプロトコルで構成する際、両端のポートを「active」に設定した場合はどうなるか？
正解：B
LACPはactive+active、またはactive+passiveでEtherChannelが形成されます。passive+passiveだけがNG（両方が相手を待っている状態）です。
Q2. EtherChannelを使うメリットとして正しいのはどれか？
正解：A
EtherChannelは複数リンクを論理的に1本にまとめることで帯域幅を拡大（最大8本）し、1本のリンク障害でも自動的に残りのリンクで通信を継続します。
Q3. PAgPのCiscoモードで積極的にEtherChannel交渉を行うモードはどれか？
正解：C（desirable）
PAgP: desirable（積極的）とauto（受動的）。LACPはactive（積極的）とpassive（受動的）。「on」は交渉プロトコルなし（静的）。

2-4 スパニングツリープロトコル（STP）

頻出 ループを防止するSTPの動作・ポート状態・Rapid STPを完全理解

🔄なぜSTPが必要か（ブロードキャストストームの問題）

スイッチのL2ループの問題

スイッチA ─── スイッチB
    │                │
   スイッチC ──────┘

のような構成でループがあると：
① PC-Aがブロードキャストを送信
② スイッチA → スイッチB・スイッチCにフラッド
③ スイッチBが受信 → スイッチC・スイッチAにフラッド
④ スイッチCが受信 → スイッチA・スイッチBにフラッド
⑤ これが無限に繰り返される = ブロードキャストストーム！
→ CPUが100%になりネットワーク全体が停止
STPはループを防ぐためにポートを「ブロック状態」にする！

🌳STPの動作（IEEE 802.1D）

STPの動作ステップ

【ステップ1】ルートブリッジの選出
  最も小さいBridge ID（Priority＋MACアドレス）のスイッチが選ばれる
  デフォルト Priority = 32768（16進数: 8000）

【ステップ2】ルートポートの選択（ルートブリッジ以外のスイッチ）
  各スイッチでルートブリッジへの最小コストのポート1本 = ルートポート（Root Port）
  コスト: 1Gbps=4, 100Mbps=19, 10Mbps=100（802.1D）

【ステップ3】指定ポートの選択（各セグメント）
  各セグメント（リンク）でルートブリッジに最も近いポート = 指定ポート（Designated Port）

【ステップ4】非指定ポートのブロック
  ルートポートでも指定ポートでもないポートはブロック（Block）状態になる

Bridge IDの構成

フィールド ビット数 デフォルト値 説明
Bridge Priority 4ビット 32768 4096単位で設定可能（0〜61440）
Extended System ID（VLAN ID） 12ビット VLAN ID PVST+ではVLAN IDが自動的に加算される
MACアドレス 48ビット 各スイッチのMAC PriorityとVLAN IDが同じ場合のタイブレーカー

STPポート状態遷移（802.1D）

状態 期間 BPDUの送受信 MAC学習 フレーム転送
Blocking 20秒（Max Age） 受信のみ なし なし
Listening 15秒（Forward Delay） 送受信 なし なし
Learning 15秒（Forward Delay） 送受信 あり なし
Forwarding — 送受信 あり あり
Disabled — なし なし なし
🚨 STPの収束時間（802.1D）： 約30〜50秒
ポートがリンクアップしてからForwarding状態になるまで約30〜50秒かかります（Blocking→Listening→Learning→Forwarding）。この遅延がPCの起動直後に通信できない原因となります。

⚡Rapid Spanning Tree（RSTP / 802.1w）

RSTpは802.1Dを改善し、収束時間を数秒以内に短縮したプロトコルです。現代のネットワークではRSTP（またはPVST+）が標準です。

項目 STP（802.1D） RSTP（802.1w）
収束時間 30〜50秒 1〜2秒
ポート状態 5状態（Block/Listen/Learn/Forward/Disable） 3状態（Discarding/Learning/Forwarding）
ポートロール Root/Designated/Non-designated Root/Designated/Alternate/Backup
BPDU ルートブリッジのみ送信 全スイッチが2秒ごとに送信

CiscoのSTP改善機能

機能 コマンド 効果
PortFast spanning-tree portfast アクセスポート（PC接続）をListening/Learning状態をスキップしてForwardingへ。起動直後から通信可能
BPDU Guard spanning-tree bpduguard enable PortFastポートでBPDU受信時にerr-disableにする。不正スイッチ接続を防ぐ
BPDU Filter spanning-tree bpdufilter enable BPDUを送受信しない。PortFastとの組み合わせで使用
Root Guard spanning-tree guard root 指定のポートがルートポートにならないように保護

ルートブリッジの手動指定

# Priorityを変更してルートブリッジに指定する（小さい値が優先）
Switch(config)# spanning-tree vlan 10 priority 4096

# マクロコマンドで自動的に optimal priority を設定
Switch(config)# spanning-tree vlan 10 root primary    # 最優先（24576）
Switch(config)# spanning-tree vlan 10 root secondary  # 次点（28672）

# STP確認コマンド
Switch# show spanning-tree
Switch# show spanning-tree vlan 10
Switch# show spanning-tree summary

✏️ 確認問題（第2-4章）

Q1. STPでルートブリッジに選出されるのはどのスイッチか？
正解：A（Bridge IDが最小）
Bridge IDは「Priority（デフォルト32768）+ VLAN ID + MACアドレス」で構成され、最も小さい値のスイッチがルートブリッジに選ばれます。管理者は意図的にPriorityを小さく設定してルートブリッジを決定します。
Q2. STP（802.1D）でポートがBlocking状態からForwarding状態になるまでの時間（デフォルト）はどれか？
正解：C（30〜50秒）
802.1D STRはBlocking(20秒)→Listening(15秒)→Learning(15秒)→Forwardingで合計50秒かかります。この問題を解決するためRSTP（802.1w）は数秒以内に収束します。
Q3. Cisco PortFast機能の説明として正しいのはどれか？
正解：D
PortFastはPC等を接続するアクセスポートで、STPのListening/Learning待機時間（30秒）をスキップしてすぐにForwarding状態にします。スイッチが接続されているポートに設定するとループの危険があります。
BPDU Guard（C）はPortFastポートでBPDUを受信した時にerr-disableにする別の機能です。
Q4. RSTPのポート状態として正しい組み合わせはどれか？
正解：B（Discarding/Learning/Forwarding）
RSTPは802.1DのBlockingとListeningをDiscardingに統合し3状態になりました。また全スイッチが積極的にBPDUを交換することで1〜2秒で収束します。

2-5 CDP・LLDP（リンク検出プロトコル）

設定 隣接機器の自動検出プロトコルを理解し活用する

🔍CDP（Cisco Discovery Protocol）

CDPはCisco独自のL2プロトコルで、物理的に接続されている隣接のCisco機器の情報を自動的に収集します。MACレベルで動作するためIPアドレスがなくても使えます。

収集できる情報 内容
デバイス識別子 隣接機器のホスト名
アドレス情報 隣接機器のIPアドレス
ポートID 隣接機器のインタフェース名（Gi0/1等）
プラットフォーム 機器の機種名（Cisco Catalyst 3750等）
機能 ルータ、スイッチ、APなどの役割
ソフトウェアバージョン IOSバージョン
ネイティブVLAN トランクポートのネイティブVLAN 
# CDPの確認コマンド
Switch# show cdp neighbors                    # 隣接機器一覧（簡略）
Switch# show cdp neighbors detail               # 隣接機器情報（詳細・IPアドレス含む）
Switch# show cdp interface GigabitEthernet0/1   # 特定IFのCDP情報

# CDPの有効・無効化
Switch(config)# no cdp run                     # グローバルで無効化
Switch(config-if)# no cdp enable              # 特定IFで無効化（セキュリティ向上）

🔍LLDP（Link Layer Discovery Protocol）

LLDPはIEEE 802.1ABで標準化されたマルチベンダー対応の隣接機器検出プロトコルです。CDPと同等の情報を収集できます。

比較項目 CDP LLDP
規格 Cisco独自 IEEE 802.1AB（国際標準）
対応機器 Cisco機器のみ マルチベンダー対応
デフォルト状態 有効（Cisco） 無効（Cisco）→ 有効化が必要
送信間隔 60秒 30秒
送信方向 双方向（送受信同一） 送信（tx）と受信（rx）を個別に制御可能 
# LLDPの有効化（グローバル）
Switch(config)# lldp run

# 送信・受信を個別に設定（インタフェース）
Switch(config-if)# lldp transmit
Switch(config-if)# lldp receive

# LLDPの確認コマンド
Switch# show lldp neighbors
Switch# show lldp neighbors detail

✏️ 確認問題（第2-5章）

Q1. CDPで収集できる情報として正しくないのはどれか？
正解：A（ユーザーアカウント情報は収集しない）
CDPはネットワーク機器の情報（ホスト名、IP、ポート名、機種、IOSバージョン等）を収集しますが、ユーザーアカウントやパスワード情報は収集しません。
Q2. LLDPとCDPの違いとして正しいのはどれか？
正解：C
LLDPはIEEE 802.1ABで定義されたマルチベンダー対応の標準プロトコルです。Ciscoスイッチではデフォルトでは無効のため「lldp run」で有効化が必要です。CDPはCisco独自でデフォルト有効です。

2-6 無線LAN WLC・Lightweight AP

頻出 コントローラベース無線LANの仕組みと管理方式を理解する

📡Autonomous AP vs Lightweight AP

比較項目 Autonomous AP（自律型） Lightweight AP（LWAP）
管理方式 各APを個別に設定・管理 WLCで一元管理
設定の変更 各APに個別にアクセス WLC1台で全AP設定変更
スケーラビリティ 低い（AP増加で管理が複雑） 高い（大規模展開に最適）
データの処理 AP自身で処理（ローカルスイッチング） WLCへトンネリング（CAPWAP）
費用 安い（WLC不要） 高い（WLCが必要）
用途 小規模（家庭・小型オフィス） 中〜大規模企業ネットワーク

🔗CAPWAP（Control and Provisioning of Wireless APs）

CAPWAPはLightweight APとWLC間の通信プロトコルです（RFC 5415）。

CAPWAP トンネルの2チャネル

  • 制御チャネル（UDP 5246）：AP管理・設定・統計情報。DTLS暗号化
  • データチャネル（UDP 5247）：クライアントのデータトラフィック。オプションでDTLS暗号化
クライアント ─ [Lightweight AP] ─ CAPWAP ─ [WLC] ─ [ネットワーク]
               ↑ 設定はWLCから     ↑ トンネル ↑ 一元管理
               CLIはWLCで           データもWLC経由

🖥️WLC（Wireless LAN Controller）

WLCの主な機能

  • 複数APの一元設定管理（SSID・チャネル・出力電力等）
  • クライアントの認証（802.1X / PSK / Open）
  • RF管理（RRM: Radio Resource Management）：チャネルと出力を自動最適化
  • クライアントのローミング管理（シームレスローミング）
  • ゲスト向けポータル認証
  • セキュリティポリシーの一元管理

🌐FlexConnect（ローカルスイッチング）

WLCへのWANが切断された場合でも、APがローカルで認証・データ転送を継続できるモードです。ブランチオフィス向け。

✏️ 確認問題（第2-6章）

Q1. Lightweight APとWLC間の通信に使用されるプロトコルはどれか？
正解：B（CAPWAP）
CAPWAPはUDP 5246（制御）と5247（データ）の2チャネルでLightweight APとWLC間を接続します。旧プロトコルLWAPP（A）は現在はCAPWAPに置き換えられています。
Q2. WLC（Wireless LAN Controller）の説明として正しいものはどれか？
正解：A
WLCは複数のLightweight APをCAPWAPプロトコルで一元管理します。SSID・セキュリティポリシー・チャネル・RFパワーを一括設定できます。Autonomous APはWLCを使わず個別管理です。
