4-3 NTP・Syslog・SNMP

頻出設定 ネットワーク運用管理の三本柱を深く理解する

🕐NTP（Network Time Protocol）

なぜ時刻同期が重要か？

「ログの時刻がバラバラでセキュリティインシデントの発生時刻が特定できない」── 実務でこれが起きると致命的です。NTPは全ネットワーク機器の時刻を統一します。

NTPの階層構造（Stratum）

Stratum 0: 原子時計・GPS（精密な時刻源）── 直接NTP通信しない
    ↓
Stratum 1: Stratum 0に直結したNTPサーバー（最上位の時刻提供サーバー）
    ↓    例: time.google.com, ntp.nict.jp
Stratum 2: Stratum 1に同期するNTPサーバー
    ↓    例: 社内のNTPサーバー
Stratum 3: Stratum 2に同期するクライアント
    ↓    例: 社内のルータ・スイッチ
  ...
Stratum 15: NTPの最大。Stratum 16は「同期不能」を意味する

ポイント:
・Stratum値が小さいほど精度が高い（信頼性が高い時刻源に近い）
・最大15ホップまで（Stratum 16 = 無効）
・UDP/123で通信

# NTPクライアント設定（外部NTPサーバーに同期）
Router(config)# ntp server 203.0.113.1          # NTPサーバーのIP
Router(config)# ntp server 203.0.113.2          # 冗長性のため複数設定可

# NTPサーバーとして動作させる（他の機器の時刻源になる）
Router(config)# ntp master 3                    # Stratum 3のサーバーとして動作

# 認証付きNTP（セキュリティ向上・不正NTPサーバー防止）
Router(config)# ntp authenticate
Router(config)# ntp authentication-key 1 md5 MyNTPkey
Router(config)# ntp trusted-key 1

# NTP確認コマンド
Router# show ntp status
Clock is synchronized, stratum 3, reference is 203.0.113.1
Router# show ntp associations
  address         ref clock     st  when  poll  reach delay  offset    disp
*~203.0.113.1     10.0.0.1      2  45    64    377   1.234  0.567    1.234
# * = 同期中のサーバー、st = Stratum
Router# show clock

📝Syslog ── ログメッセージの集中管理

Syslogの仕組みと重要性

ネットワーク機器は常に様々なイベント（リンクダウン・設定変更・認証失敗等）をログとして出力しています。Syslogはこれらのログを中央のSyslogサーバーに集約する仕組みです。

Syslogの重大度レベル（必須暗記！）

レベル番号 名称 説明 キーワード
0 Emergency システムが使用不能 emergencies
1 Alert 即座に対応が必要 alerts
2 Critical 重大な状態 critical
3 Error エラー状態 errors
4 Warning 警告（問題が起きる可能性） warnings
5 Notification 正常だが重要なイベント notifications
6 Informational 情報メッセージ informational
7 Debugging デバッグメッセージ debugging
💡 覚え方: 「Every Awesome Cisco Engineer Will Need Ice-cream Daily」
Emergency(0), Alert(1), Critical(2), Error(3), Warning(4), Notification(5), Informational(6), Debugging(7)
レベル番号が小さいほど重大。「logging trap 4」と設定すると、レベル0〜4（warning以上）のログをSyslogサーバーに送信します。 
# Syslogサーバーへのログ転送設定
Router(config)# logging host 10.0.0.200           # Syslogサーバーのアドレス
Router(config)# logging trap informational        # レベル6以上を送信
Router(config)# logging source-interface Loopback0  # 安定した送信元IFを指定

# タイムスタンプの有効化（NTPと組み合わせて正確な時刻をログに記録）
Router(config)# service timestamps log datetime msec

# Syslog確認
Router# show logging
*Mar  4 10:15:32.123: %LINK-3-UPDOWN: Interface GigabitEthernet0/0, changed state to down
*Mar  4 10:15:33.456: %LINEPROTO-5-UPDOWN: Line protocol on Interface Gi0/0, changed state to down
# ↑ %LINK-3-UPDOWN のフォーマット: %機能-レベル-メッセージ名

📊SNMP（Simple Network Management Protocol）

SNMPはネットワーク機器をリモートで監視・管理するためのプロトコルです。CPU使用率、メモリ使用量、トラフィック量などをリアルタイムで収集できます。

SNMPの構成要素

構成要素 役割 通信方向
NMS（Network Management Station） 管理サーバー。機器の情報を収集・分析 Get/Set → エージェント
SNMPエージェント ルータ、スイッチ等の監視対象機器にインストールされたソフトウェア 応答/Trap → NMS
MIB（Management Information Base） 監視データベース。OID（Object ID）で各パラメータを一意に識別 —

SNMPバージョン比較

比較項目 SNMPv1 SNMPv2c SNMPv3
認証 コミュニティストリング（平文） コミュニティストリング（平文） ユーザー名+パスワード
暗号化 なし なし あり（AES/DES）
セキュリティ 弱い 弱い 強い（推奨）
GetBulk なし あり（効率的な大量取得） あり
🚨 セキュリティ上、SNMPv3が推奨
SNMPv1/v2cの「コミュニティストリング」は平文で通信されるため傍受されるリスクがあります。特にSNMPv1/v2cのRW（Read-Write）コミュニティが漏洩すると、攻撃者がルータの設定を変更できてしまいます。実務ではSNMPv3のauthPriv（認証+暗号化）を使用すべきです。 
# SNMPv2c設定（シンプル）
Router(config)# snmp-server community ReadOnly RO     # 読み取り専用コミュニティ
Router(config)# snmp-server community ReadWrite RW   # 読み書きコミュニティ（危険！）
Router(config)# snmp-server host 10.0.0.200 version 2c ReadOnly
Router(config)# snmp-server enable traps            # Trapを有効化

# SNMPv3設定（セキュア・推奨）
Router(config)# snmp-server group ADMIN v3 priv
Router(config)# snmp-server user admin1 ADMIN v3 auth sha AuthPass123 priv aes 128 PrivPass456

✏️ 確認問題（第4-3章）

Q1. NTPのStratum値について正しいのはどれか？
正解：B
Stratum 0は原子時計等の時刻源そのもの（NTP通信はしない）。Stratum 1がStratum 0に直結した最上位NTPサーバー。数値が増えるほど時刻源から遠くなり精度が下がります。Stratum 15が最大で16は「同期不能」を意味します。
Q2. Syslogで「logging trap 4」と設定した場合に送信されるログレベルはどれか？
正解：C（レベル0〜4）
指定したレベル以上（数値が小さい方向）のログが送信されます。logging trap 4 なら Warning(4), Error(3), Critical(2), Alert(1), Emergency(0) が対象です。Informational(6)やDebugging(7)は含まれません。
Q3. SNMP v1/v2cとv3の最大の違いは何か？
正解：D
v1/v2cはコミュニティストリング（平文のパスワード）で認証するため傍受に弱い。v3はユーザーベースの認証（SHA/MD5）と暗号化（AES/DES）を提供し、セキュリティが大幅に向上しています。GetBulkはv2cで追加された機能です。

4-4 QoS・SSH・TFTP/FTP

頻出 トラフィックの優先制御とファイル転送プロトコルを理解する

⚡QoS（Quality of Service）── なぜ必要か？

ネットワーク帯域幅は有限です。Webブラウジング、ファイルダウンロード、音声通話、ビデオ会議がすべて同じ帯域を奪い合うと、音声が途切れたりビデオが乱れたりします。QoSは重要なトラフィックを優先的に処理する仕組みです。

QoSの3つのメカニズム

メカニズム 説明 実例
分類とマーキング トラフィックを種類ごとに分類し、パケットにラベル（マーキング）を付ける VoIPパケットにDSCP EF(46)をマーク
キューイング マーキングに基づいてキュー（待ち行列）に振り分け、優先度の高いキューから先に送信 音声キューは最優先で処理
輻輳管理/輻輳回避 ネットワークが混雑した時の対処方法 WRED（重要度の低いパケットから先に破棄）

マーキングの仕組み ── DSCP値（頻出！）

DSCP（Differentiated Services Code Point）

IPヘッダのToS（Type of Service）フィールドの上位6ビットを使ってパケットの優先度を示します。

DSCP名 DSCP値（10進） 用途
EF（Expedited Forwarding） 46 VoIP音声 ── 最優先、低遅延・低ジッター・低損失を保証
AF41 34 ビデオ会議
AF31 26 重要データ（業務アプリ等）
AF21 18 一般データ
CS0 / DF（Default） 0 ベストエフォート（通常のWebトラフィック等）
💡 CCNAで覚えるポイント
  • EF(46) = VoIP音声。遅延・ジッター・パケットロスに最も敏感
  • AF(Assured Forwarding) = クラス(1〜4)×ドロップ優先度(1〜3)で定義
  • マーキングはできるだけネットワークのエッジ（入口）で行うのがベストプラクティス
  • L2ではCoS（802.1Qタグの3ビット）、L3ではDSCP（IPヘッダの6ビット）でマーキング

🔐SSH vs Telnet

比較項目 Telnet SSH
ポート番号 TCP/23 TCP/22
暗号化 なし（平文）→ 盗聴可能！ あり→ 安全
推奨 使用禁止 推奨 
# SSH設定（Telnetは絶対に使わない！）
Router(config)# hostname R1                          # ホスト名設定（SSH必須）
R1(config)# ip domain-name example.com              # ドメイン名（RSAキー生成に必須）
R1(config)# crypto key generate rsa modulus 2048   # RSAキーペア生成（2048ビット推奨）
R1(config)# ip ssh version 2                        # SSHv2に限定（v1は脆弱性あり）
R1(config)# username admin secret StrongP@ss1     # ローカルユーザー作成
R1(config)# line vty 0 4
R1(config-line)# transport input ssh                # SSHのみ許可（Telnet拒否）
R1(config-line)# login local                        # ローカルユーザーDBで認証

📂TFTP・FTP・SFTP

プロトコル ポート 認証 暗号化 用途
TFTP UDP/69 なし なし IOSイメージ・設定ファイルの簡易転送
FTP TCP/20(データ),21(制御) あり（平文） なし ファイル転送（平文のため非推奨）
SFTP/SCP TCP/22（SSH上） あり あり セキュアなファイル転送（推奨）

✏️ 確認問題（第4-4章）

Q1. VoIP音声トラフィックに割り当てるべきDSCP値はどれか？
正解：A（EF = 46）
EF（Expedited Forwarding）はVoIP音声のために設計されたDSCP値です。低遅延・低ジッター・低パケットロスを保証します。ビデオ会議はAF41、通常のWebはDF(0)です。
Q2.【シナリオ】Telnetでリモート管理しているルータをSSHに移行するために必要な手順として正しくないのはどれか？
正解：C（SNMPはSSH設定に無関係）
SSH設定に必要なのは: ①ホスト名+ドメイン名 ②RSAキー生成 ③ユーザー作成 ④VTYラインでSSHのみ許可。SNMPはネットワーク監視プロトコルでSSHとは無関係です。
Q3. FTPの制御チャネルとデータチャネルのポート番号の組み合わせとして正しいのはどれか？
正解：B（制御=21、データ=20）
FTPは2つのチャネルを使います。TCP/21は制御（コマンド送受信）、TCP/20はデータ転送用です。紛らわしいですが「制御が21、データが20」の順序で覚えましょう。TFTPはUDP/69で1チャネルのみです。
