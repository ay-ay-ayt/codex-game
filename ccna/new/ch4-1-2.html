4-1 NAT・PAT（ネットワークアドレス変換）

頻出設定 プライベートIPからインターネットに出るための仕組みを根本から理解する

🔄なぜNATが必要なのか？ ── 問題の本質を理解する

まず「なぜNATが必要か」を理解しないと、NATの仕組みも設定も暗記になってしまいます。

IPv4アドレスの枯渇問題

IPv4は32ビット = 約43億個のアドレスしかありません。世界中のデバイスすべてにユニークなパブリックIPを割り当てることは不可能です。

そこで考え出されたのが「社内ではプライベートIP（RFC 1918）を使い、インターネットに出る時だけパブリックIPに変換する」という仕組み = NATです。

【NATなしの世界（不可能）】
社内PC 100台すべてにパブリックIP必要 → 非現実的 + 費用莫大

【NATありの世界（現実）】
社内PC 100台: 192.168.1.1 〜 192.168.1.100（プライベートIP = 無料）
ルータ:       1つのパブリックIP 203.0.113.50 を持つ
NATが変換:    192.168.1.x → 203.0.113.50 としてインターネットへ出る

📌NATの用語 ── 4つのアドレスを区別する

NATでは4つのアドレスが登場します。これを混同すると問題が解けません。

用語 意味 具体例
Inside Local 内部ネットワークのホストに設定されたプライベートIP 192.168.1.10
Inside Global 内部ホストがインターネット上で使うパブリックIP（変換後） 203.0.113.50
Outside Local 外部ホストが内部から見えるIP（通常はOutside Globalと同じ） 8.8.8.8
Outside Global 外部ホストに割り当てられた実際のIP 8.8.8.8
🚨 覚え方のコツ
Inside/Outside = 「自社ネットワークの中か外か」
Local/Global = 「変換前(Local)か変換後(Global)か」
Inside Local → Inside Global への変換がNATの本質です。

🔎 パケットの変換を追いかけてみよう

【シナリオ】 社内PC(192.168.1.10) が Google DNS(8.8.8.8) にアクセス

① PCがパケット送信
   送信元: 192.168.1.10 (Inside Local)   宛先: 8.8.8.8

② ルータのNATがパケットを変換（送信時）
   送信元: 203.0.113.50 (Inside Global)  宛先: 8.8.8.8
   ※ NATテーブルに 192.168.1.10 ⇄ 203.0.113.50 のマッピングを記録

③ Google DNSが応答を返す
   送信元: 8.8.8.8   宛先: 203.0.113.50 (Inside Global)

④ ルータのNATが逆変換（受信時）
   送信元: 8.8.8.8   宛先: 192.168.1.10 (Inside Local)
   ※ NATテーブルのマッピングを参照して元のプライベートIPに戻す

⑤ PCがパケットを受信
   PCは自分が直接 8.8.8.8 と通信したかのように見える

📊NATの3つの種類 ── 違いを完全に理解する

① スタティックNAT（Static NAT）

1対1の固定マッピング

1つのプライベートIPと1つのパブリックIPを永久に固定で対応させます。Webサーバー等、外部からアクセスされるサーバーに使います。

192.168.1.10 ⇄ 203.0.113.10  （常にこの対応で変換）
192.168.1.11 ⇄ 203.0.113.11  （別のサーバー用）

メリット: 外部から内部サーバーに常にアクセス可能
デメリット: パブリックIPを1台ずつ消費 → 費用がかかる
用途: DMZのWebサーバー、メールサーバー

② ダイナミックNAT（Dynamic NAT）

多対多のプール変換

パブリックIPの「プール」を作り、内部ホストが通信を開始するとプールから1つ割り当てます。プールが空くと別のホストに再割り当て。

パブリックIPプール: 203.0.113.10 〜 203.0.113.14（5個）

PC-A(192.168.1.10)が通信開始 → 203.0.113.10を割り当て
PC-B(192.168.1.11)が通信開始 → 203.0.113.11を割り当て
...
PC-F(192.168.1.15)が通信開始 → プール枯渇！ → 通信できない ✗

メリット: スタティックNATよりは柔軟（プール内で再利用）
デメリット: 同時接続数 = パブリックIP数の制限あり

③ PAT / NAT Overload（最重要！）

多対1のポート番号変換 ── 実務で最も使われるNAT

PATは1つのパブリックIPを複数の内部ホストで共有します。各接続をL4のポート番号で区別します。

変換テーブル:
  192.168.1.10:50001 → 203.0.113.50:50001
  192.168.1.11:50002 → 203.0.113.50:50002
  192.168.1.12:50003 → 203.0.113.50:50003
  ...（数千〜数万の同時接続が可能！）

パブリックIP = 203.0.113.50 の1つだけで何千台もインターネットに出られる

仕組み:
  ・送信元ポート番号をNATが書き換えて、各内部ホストを区別
  ・応答が返ると、宛先ポート番号を見て元の内部ホストに転送
  ・ポート番号は0〜65535（約65000通り）あるので多くの接続が可能
🚨 試験では「PAT」と「NAT Overload」は同じ意味！
「ip nat inside source list 1 interface Gi0/0 overload」のoverloadがPATを有効にするキーワードです。overloadがないとダイナミックNAT（1対1のプール変換）です。家庭のWi-Fiルータは全部PATを使っています。

⚙️NAT設定 ── 構文と実践的な設定例

設定の全体像

NAT設定に必要な3ステップ:
① 内側・外側インタフェースの指定（ip nat inside / ip nat outside）
② 変換対象の定義（ACLまたは手動マッピング）
③ 変換ルールの設定（ip nat inside source ...）

═══════════════════════════════════════════════
# 【PAT設定 ── 最も一般的。必ず覚える！】
═══════════════════════════════════════════════

# ステップ1: 内側インタフェースの指定
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip nat inside      # ← これがinsideの宣言

# ステップ2: 外側インタフェースの指定
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip address 203.0.113.50 255.255.255.0
Router(config-if)# ip nat outside     # ← これがoutsideの宣言

# ステップ3: 変換対象のACL作成
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255

# ステップ4: PATの設定（overloadがPATのポイント！）
Router(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload
# ↑ ACL 1に該当する通信をGi0/1のIPでPAT変換 + overload = ポート共有

═══════════════════════════════════════════════
# 【スタティックNAT設定 ── サーバー用】
═══════════════════════════════════════════════
Router(config)# ip nat inside source static 192.168.1.100 203.0.113.100
# ↑ 192.168.1.100 と 203.0.113.100 を1対1で固定変換

═══════════════════════════════════════════════
# 【NATの確認・トラブルシューティング】
═══════════════════════════════════════════════
Router# show ip nat translations
Pro  Inside global     Inside local       Outside local      Outside global
tcp  203.0.113.50:1024 192.168.1.10:50001 8.8.8.8:53         8.8.8.8:53
tcp  203.0.113.50:1025 192.168.1.11:60010 142.250.80.46:443  142.250.80.46:443
---  203.0.113.100     192.168.1.100      ---                ---

Router# show ip nat statistics     # 変換回数・ヒット数の統計
Router# clear ip nat translation *   # NATテーブルをクリア（トラブル時に使用）
Router# debug ip nat              # リアルタイムでNAT変換を監視（デバッグ用）

🔧 NATのトラブルシューティング

NATが動かない時のチェックリスト

  1. ip nat inside / ip nat outside がインタフェースに設定されているか？ → show ip nat statistics で確認
  2. ACLが正しいか？ ワイルドカードマスクの範囲が変換対象をカバーしているか？
  3. overloadを忘れていないか？（PATの場合）
  4. inside / outsideの方向が逆になっていないか？（よくあるミス！）
  5. スタティックNATの場合、ip nat inside source staticの引数の順序（local → global）が正しいか？

✏️ 確認問題（第4-1章）

Q1. 社内PCのIP 192.168.1.10 がインターネットに出る際に使用されるパブリックIP 203.0.113.50 は、NATの用語でどれに該当するか？
正解：C（Inside Global）
Inside = 内部ホスト、Global = 変換後。つまりInside Globalは「内部ホストがインターネット上で使うパブリックIP」です。元のプライベートIP 192.168.1.10 は Inside Local です。
Q2. PAT（NAT overload）が1つのパブリックIPで多数の内部ホストを同時にインターネット接続できる仕組みとして正しいのはどれか？
正解：D
PATは送信元ポート番号を書き換えてセッションごとに一意のポート番号を割り当てます。応答時はそのポート番号を見て元のホストに転送します。1つのIPで約65000セッション区別可能です。
Q3.【シナリオ問題】以下のNAT設定をルータに投入したが、インターネットに接続できない。原因として最も可能性が高いのはどれか？
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface Gi0/1
正解：B
interfaceキーワードで出力IFのIPをNATソースに使う場合、overloadがないとPATにならず、かつプールも指定されていないためダイナミックNATとしても成立しません。正しくは「ip nat inside source list 1 interface Gi0/1 overload」です。また、ip nat inside/outsideがインタフェースに設定されているかも確認必要です。
Q4. show ip nat translations の出力で「Inside local」が 192.168.1.10、「Inside global」が 203.0.113.50:1024 と表示されている。この変換方式はどれか？
正解：A（PAT）
Inside Globalにポート番号（:1024）が付いているのはPATの特徴です。スタティックNATやダイナミックNATは1対1変換のためポート番号を変換しません。PATは複数ホストを区別するためにポート番号を使います。
Q5.【実務シナリオ】社内にWebサーバー(192.168.1.100)があり、インターネットからのアクセスを許可したい。どのNAT方式を使うべきか？
正解：C（スタティックNAT）
外部からアクセスされるサーバーは常に同じパブリックIPで到達可能でなければなりません。スタティックNATで固定の1対1マッピングを作ることで、外部クライアントは常に同じIPでサーバーにアクセスできます。PATやダイナミックNATは動的にマッピングが変わるため外部からの着信接続には不向きです。

4-2 DHCP・DNS

頻出設定 IPアドレスの自動配布と名前解決の仕組みを深く理解する

📋DHCP（Dynamic Host Configuration Protocol）

DHCPが解決する問題

100台のPCに手動でIPアドレス・サブネットマスク・デフォルトゲートウェイ・DNSサーバーを設定するのは非現実的です。DHCPはネットワーク設定を自動で配布する仕組みです。

DORA ── DHCPの4ステップを完全に理解する

クライアント                        DHCPサーバー
(IPなし:0.0.0.0)                   (例:192.168.1.1)
    |                                    |
    |─── ① Discover(ブロードキャスト) →|   「誰かIPアドレスをください！」
    |    送信元:0.0.0.0  宛先:255.255.255.255（L2ブロードキャスト）
    |                                    |
    |←─ ② Offer(ユニキャスト) ─────|   「192.168.1.50を使いませんか？」
    |    DHCPサーバーが使えるIPを提案     |
    |                                    |
    |─── ③ Request(ブロードキャスト) →|   「はい、192.168.1.50をください！」
    |    ブロードキャストで送信（他のDHCPサーバーにも断りを入れるため）
    |                                    |
    |←─ ④ Ack(ユニキャスト) ──────|   「承認！リース時間は24時間です」
    |    IP, サブネットマスク, GW, DNS     |
    |    の情報をすべて配布               |
    |                                    |
    | ≪通信開始！≫                       |

重要ポイント:
・Discover と Request は「ブロードキャスト」（クライアントはまだIPを持たない）
・Offer と Ack は通常「ユニキャスト」
・覚え方: DORA = Discover → Offer → Request → Ack
💡 なぜRequestもブロードキャストなのか？
ネットワーク上に複数のDHCPサーバーがある場合、Discoverに対して複数のOfferが返ってくることがあります。Requestをブロードキャストで送ることで「このサーバーのOfferを選びました」と全DHCPサーバーに通知し、選ばれなかったサーバーはIPを解放します。

DHCPリレーエージェント ── 別サブネットの問題

なぜリレーエージェントが必要か

DHCPのDiscoverはブロードキャストです。ルータはブロードキャストを転送しません。つまり、DHCPサーバーとクライアントが別サブネットにいると、Discoverが届きません。 

[PC] ─── Discover(ブロードキャスト) ─→ [ルータ] ✗ ブロードキャストは通さない ──→ [DHCPサーバー]
                                         ↓
                              ip helper-address 設定！
                                         ↓
[PC] ─── Discover ─→ [ルータがユニキャストに変換] → [DHCPサーバー]

═══════════════════════════════════════════════
# 【CiscoルータをDHCPサーバーにする設定】
═══════════════════════════════════════════════
Router(config)# ip dhcp pool LAN-POOL             # DHCPプール作成
Router(dhcp-config)# network 192.168.1.0 255.255.255.0  # 配布するサブネット
Router(dhcp-config)# default-router 192.168.1.1     # デフォルトゲートウェイ
Router(dhcp-config)# dns-server 8.8.8.8 8.8.4.4  # DNSサーバー
Router(dhcp-config)# lease 7                        # リース期間7日
Router(dhcp-config)# domain-name example.com      # ドメイン名

# 除外アドレス（ゲートウェイやサーバーに静的IPを使う場合）
Router(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10

# DHCPリレーエージェント（別サブネットのDHCPサーバーを使う場合）
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip helper-address 10.0.0.100  # DHCPサーバーのIP

# DHCP確認コマンド
Router# show ip dhcp binding            # リース中のIP一覧
IP address       Client-ID       Lease expiration      Type
192.168.1.50     0100.1234.5678  Mar 10 2026 10:00 AM  Automatic
192.168.1.51     0100.abcd.ef01  Mar 10 2026 10:05 AM  Automatic

Router# show ip dhcp pool               # DHCPプールの概要
Router# show ip dhcp conflict           # IPアドレスの競合を確認

🌐DNS（Domain Name System）

DNSが解決する問題

人間は「google.com」と覚えますが、コンピュータは「142.250.80.46」のようなIPアドレスでしか通信できません。DNSはドメイン名をIPアドレスに変換します（名前解決）。

DNS名前解決の流れ（再帰問い合わせ）

ユーザーが「www.example.com」にアクセス:

① PC → ローカルDNSキャッシュを確認（過去の問い合わせ結果がなければ②へ）
② PC → 設定されたDNSサーバー（再帰リゾルバ）に問い合わせ
③ 再帰リゾルバ → ルートDNSサーバーに問い合わせ「.comは？」
   → 「.comの権威サーバーはa.gtld-servers.net」（Referral）
④ 再帰リゾルバ → .com権威サーバーに「example.comは？」
   → 「example.comの権威サーバーはns1.example.com」（Referral）
⑤ 再帰リゾルバ → example.com権威サーバーに「www.example.comは？」
   → 「93.184.216.34」（A レコード）
⑥ 再帰リゾルバ → PC に「93.184.216.34」を返す + キャッシュ保存

DNSレコードの種類

レコード 正式名 用途 例
A Address ドメイン → IPv4アドレス www.example.com → 93.184.216.34
AAAA IPv6 Address ドメイン → IPv6アドレス www.example.com → 2606:2800:...
CNAME Canonical Name ドメインのエイリアス（別名） mail.example.com → exchange.example.com
MX Mail Exchanger メールサーバーの指定 example.com → mail.example.com (priority 10)
PTR Pointer IPアドレス → ドメイン（逆引き） 93.184.216.34 → www.example.com
NS Name Server ゾーンの権威DNSサーバー example.com → ns1.example.com
SOA Start of Authority ゾーンの管理情報（シリアル番号等） — 
# CiscoルータでのDNS設定
Router(config)# ip domain-name example.com      # ドメイン名設定
Router(config)# ip name-server 8.8.8.8          # DNSサーバー指定
Router(config)# ip domain-lookup                # DNS問い合わせ有効（デフォルト有効）
Router(config)# no ip domain-lookup             # DNS無効（タイプミスで遅延するのを防ぐ作業用）
💡 実務Tips: no ip domain-lookup
CiscoデSLIで「show ip rout」のようなタイプミスをすると、ルータがDNS名前解決を試みて長時間待たされることがあります。作業中は「no ip domain-lookup」で DNS問い合わせを無効にしておくと快適です。

✏️ 確認問題（第4-2章）

Q1. DHCPのDORAプロセスで、クライアントが最初に送信するメッセージはどれか？
正解：B（Discover）
DORA = Discover→Offer→Request→Ack。クライアントはまだIPアドレスを持たないため、送信元0.0.0.0、宛先255.255.255.255のブロードキャストでDiscoverを送信します。
Q2.【シナリオ】DHCPサーバーとクライアントが異なるサブネットにいる。クライアントがIPを取得できない。解決策はどれか？
正解：A
ip helper-addressを設定するとルータがDHCPブロードキャストをユニキャストに変換してDHCPサーバーに転送します。設定場所はクライアント側のインタフェース（inside IF）です。Bも動作はしますが物理的な移動が必要であり最善策ではありません。
Q3. ドメイン名からIPv4アドレスへの正引きに使われるDNSレコードの種類はどれか？
正解：D（Aレコード）
Aレコードはドメイン名→IPv4アドレスの正引き。AAAAはIPv6の正引き。PTRはIPアドレス→ドメイン名の逆引き。MXはメールサーバーの指定です。
Q4. ip dhcp excluded-address コマンドの目的として正しいのはどれか？
正解：C
excluded-addressはプール範囲内でDHCPが配布しないIPを指定します。ゲートウェイのIP（例:192.168.1.1）やサーバーの固定IPをDHCPが配布してしまうのを防ぐために使います。
