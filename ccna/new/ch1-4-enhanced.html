1-4 IPv6アドレス

超頻出設定 IPv6はCCNA試験で確実に出題される重要トピック。アドレス体系・自動設定・NDP・設定コマンドを完全理解する

🌐なぜIPv6が必要か？

IPv4の限界とIPv6の登場

IPv4は32ビット（約43億個）のアドレスしかありません。NATで延命してきましたが、IoTの普及で根本的に不足しています。IPv6は128ビット（約3.4×10^38個）のアドレスを持ち、「地球上のすべての砂粒にIPを振ってもまだ余る」と言われています。 

IPv4:   32ビット  → 約43億個        例: 192.168.1.1
IPv6:  128ビット  → 約340澗(かん)個  例: 2001:0db8:85a3:0000:0000:8a2e:0370:7334

IPv6の利点:
✅ 膨大なアドレス空間 → NATが原則不要（End-to-End通信の復活）
✅ ヘッダの簡素化 → ルータの処理負荷軽減
✅ 自動設定機能（SLAAC） → DHCPサーバーなしでもIPアドレスを取得可能
✅ IPsec標準搭載 → セキュリティ向上
✅ ブロードキャストなし → マルチキャストで代替

📝IPv6アドレスの表記法

128ビットを16進数で表記する

完全表記:  2001:0db8:85a3:0000:0000:8a2e:0370:7334
           ←── 8グループ × 16ビット(4桁の16進数) = 128ビット ──→

【省略ルール1】 各グループの先頭の0は省略できる
  2001:0db8:85a3:0000:0000:8a2e:0370:7334
→ 2001:db8:85a3:0:0:8a2e:370:7334

【省略ルール2】 連続する0のグループは :: で省略できる（1回だけ！）
→ 2001:db8:85a3::8a2e:370:7334
  ※ :: は「ここに0のグループが入る」を意味する
  ※ :: は1つのアドレス内で1回しか使えない（曖昧さを防ぐため）

【練習問題】以下のアドレスを省略形に変換してみよう:
  fe80:0000:0000:0000:0211:22ff:fe33:4455
→ fe80::211:22ff:fe33:4455

  2001:0db8:0000:0001:0000:0000:0000:0001
→ 2001:db8:0:1::1
  ※ 0が連続する最も長い部分を :: に置き換える
🚨 試験でよくある引っかけ
  • :: は1つのアドレス内で1回だけ使用可能
  • 2001:db8::1::2 は無効（::が2回使われている）
  • 2001:db8:0:0:1:0:0:1 → 2001:db8::1:0:0:1 が正しい省略（最も長い連続する0のグループを::に置換）

📊IPv6アドレスの種類 ── CCNAで必須の5タイプ

種類 プレフィックス 用途 IPv4の相当
グローバルユニキャスト (GUA) 2000::/3（通常 2001:で始まる） インターネット上で一意なアドレス（パブリックIP相当） パブリックIPv4
リンクローカル (LLA) fe80::/10 同一リンク（サブネット）内でのみ有効。自動生成される 169.254.x.x (APIPA)
ユニークローカル (ULA) fc00::/7（通常 fd で始まる） プライベートネットワーク内のみ（ルーティング不可） 10.x.x.x / 172.16-31 / 192.168.x.x
マルチキャスト ff00::/8 1対多の通信（ブロードキャストの代替） 224.0.0.0/4
ループバック ::1/128 自分自身への通信テスト 127.0.0.1

重要なマルチキャストアドレス（必須暗記！）

アドレス 名称 用途
ff02::1 全ノード（All Nodes） リンク上の全デバイスに送信（IPv4のブロードキャスト相当）
ff02::2 全ルータ（All Routers） リンク上の全ルータに送信
ff02::5 全OSPFルータ OSPFv3で使用
ff02::6 OSPF DR/BDR OSPFv3のDR/BDR向け
ff02::1:ff__:____ 要請ノードマルチキャスト NDP（近隣探索）で使用。ユニキャストアドレスの下位24ビットから生成
💡 リンクローカルアドレス(LLA)は必ず存在する
IPv6が有効な全インタフェースには、GUAの設定有無に関わらず自動的にリンクローカルアドレスが生成されます。LLAはルーティングプロトコル（OSPFv3等）のネクストホップアドレスとして使われるため非常に重要です。

🔧EUI-64 ── MACアドレスからインタフェースIDを生成

EUI-64の変換手順（試験で計算問題あり！）

MACアドレス: 00:1A:2B:3C:4D:5E（48ビット）

Step1: MACを前半3オクテット(OUI)と後半3オクテットに分離
  00:1A:2B | 3C:4D:5E

Step2: 中間にFF:FEを挿入して64ビットに拡張
  00:1A:2B:FF:FE:3C:4D:5E

Step3: 先頭バイトの第7ビット（U/Lビット）を反転
  00 = 0000 0000 → 第7ビット反転 → 0000 0010 = 02
  結果: 02:1A:2B:FF:FE:3C:4D:5E

Step4: IPv6表記に変換（4桁ずつグループ化）
  インタフェースID: 021a:2bff:fe3c:4d5e

完成: GUA プレフィックス + EUI-64 インタフェースID
  例: 2001:db8:1:1: + 021a:2bff:fe3c:4d5e
  →   2001:db8:1:1:21a:2bff:fe3c:4d5e

【EUI-64の見分け方】
  インタフェースID部分に「FF:FE」が含まれていたら EUI-64 で生成されたアドレス！

📡SLAAC ── サーバー不要の自動アドレス設定

SLAAC（Stateless Address Auto-Configuration）は、DHCPサーバーなしでホストが自分のIPv6アドレスを自動生成する仕組みです。IPv6の最大の特徴の一つです。

SLAACの動作フロー（重要！）

ホスト(PC)                           ルータ(R1)
  |                                    |
  |── RS（Router Solicitation）──→|   ff02::2（全ルータ宛）に送信
  |   「ルータさん、ネットワーク情報ください」   |
  |                                    |
  |←── RA（Router Advertisement）──|   ff02::1（全ノード宛）に送信
  |   「プレフィックスは 2001:db8:1:1::/64、     |
  |     デフォルトGWは fe80::1 です」            |
  |                                    |
  | ホストが自動でアドレス生成:                     |
  | プレフィックス(64ビット) + インタフェースID(64ビット) |
  | = 2001:db8:1:1:021a:2bff:fe3c:4d5e/64       |
  |                                    |
  |── DAD（重複アドレス検出）──→|   生成したアドレスが重複していないか確認
  |   NS（Neighbor Solicitation）        |   重複なし → アドレス確定！
  |                                    |

RAに含まれるフラグ:
  Aフラグ = 1: SLAAC使用可（ホストが自動設定）
  Oフラグ = 1: DHCPv6から追加情報取得（DNS等）→ ステートレスDHCPv6
  Mフラグ = 1: DHCPv6からアドレスも取得 → ステートフルDHCPv6

3つのIPv6アドレス取得方法の比較

方式 アドレス取得 DNSサーバー情報 RAフラグ DHCPv6サーバー
SLAAC（のみ） RA + EUI-64/ランダム RAから取得（RDNSS） A=1, O=0, M=0 不要
ステートレスDHCPv6 RA + EUI-64/ランダム DHCPv6サーバーから A=1, O=1, M=0 必要（DNS等のみ提供）
ステートフルDHCPv6 DHCPv6サーバーから DHCPv6サーバーから A=0, M=1 必要（アドレス+その他）

🔍NDP（近隣探索プロトコル）── IPv6のARP代替

IPv6にはARPがありません。代わりにICMPv6ベースのNDPが同様の機能を提供します。

NDPメッセージ 略称 ICMPv6タイプ 用途 IPv4の相当
Router Solicitation RS 133 ルータにRAを要求 （なし）
Router Advertisement RA 134 プレフィックス・GW情報を通知 （DHCP応答に類似）
Neighbor Solicitation NS 135 特定IPのMACアドレスを問い合わせ / DAD ARP Request
Neighbor Advertisement NA 136 NSへの応答（MACアドレスを通知） ARP Reply
Redirect — 137 より適切なネクストホップを通知 ICMP Redirect
🚨 DAD（Duplicate Address Detection）は必ず覚える
ホストが新しいIPv6アドレスを設定する時（SLAAC・手動どちらでも）、まずNS（Neighbor Solicitation）を要請ノードマルチキャストアドレスに送信して、アドレスの重複がないか確認します。応答がなければアドレスを確定します。

🛡️IPv6 ACL

IPv6のACLは名前付き拡張ACLのみ（番号付きACLはない）。構文はIPv4と似ていますが違いもあります。

IPv4 ACLとの違い:
① 名前付きACLのみ（番号なし）
② 適用コマンドが ipv6 traffic-filter（ip access-group ではない）
③ 末尾に暗黙の permit icmpv6 がある（NDPを壊さないため）
④ ワイルドカードマスクの代わりにプレフィックス長を使用

Router(config)# ipv6 access-list BLOCK-TELNET
Router(config-ipv6-acl)# deny tcp any any eq 23
Router(config-ipv6-acl)# permit ipv6 any any

Router(config)# interface Gi0/0
Router(config-if)# ipv6 traffic-filter BLOCK-TELNET in

確認: show ipv6 access-list

✏️ 確認問題（第1-4章）

Q1. IPv6アドレス 2001:0db8:0000:0000:0000:0000:0000:0001 の正しい省略形はどれか？
正解：C
::: （Aの3つのコロン）は無効表記。Dは::が2回使われているので無効。Bは省略可能だが最も簡潔な形はCです。連続する0のグループを::で置き換えます。
Q2. MACアドレス 00:1A:2B:3C:4D:5E からEUI-64でインタフェースIDを生成した場合、正しい結果はどれか？
正解：B
EUI-64の手順: ①MACを半分に分割(00:1A:2B | 3C:4D:5E) ②中間にFF:FEを挿入(00:1A:2B:FF:FE:3C:4D:5E) ③第7ビット反転(00→02)。結果: 021a:2bff:fe3c:4d5e。Cは第7ビットの反転を忘れています。
Q3. SLAACでホストがIPv6アドレスを自動設定する際に使用されるNDPメッセージの組み合わせとして正しいのはどれか？
正解：A
SLAACではホストがRS(ff02::2宛)を送信してルータにネットワーク情報を要求し、ルータがRA(ff02::1宛)でプレフィックス情報を返します。B(NS/NA)はMACアドレス解決とDADに使用。DHCPv6は別のメカニズム。ARPはIPv4のみ。
Q4. IPv6のリンクローカルアドレスについて正しいのはどれか？（2つ選べ）
正解：D
LLAはfe80::/10（ff80ではない！）で始まり、IPv6が有効な全インタフェースに自動生成されます。ルータを越えることはできません（同一リンク内のみ）。OSPFv3のネクストホップ、NDP、DHCPv6リレーなど重要な用途があります。手動設定も可能（推奨）。
Q5.【show出力問題】以下のshow ipv6 interface briefの出力を見て、このルータのGi0/0に設定されているグローバルユニキャストアドレスはどれか？
GigabitEthernet0/0 [up/up]
FE80::1
2001:DB8:ACAD:1::1
正解：C
FE80::はリンクローカル。2001:で始まるアドレスがグローバルユニキャスト(GUA)です。FF02::はマルチキャスト、::1はループバックです。show ipv6 interface briefでは各IFのLLAとGUAが表示されます。
Q6. ステートレスDHCPv6の特徴を示すRAフラグの組み合わせはどれか？
正解：B
ステートレスDHCPv6: アドレスはSLAAC(A=1)で取得、DNSサーバー等の追加情報はDHCPv6から取得(O=1)。Mフラグが1の場合はステートフルDHCPv6（アドレスもDHCPv6から取得）。
Q7. IPv6で、IPv4のARPに相当する機能を提供するプロトコルはどれか？
正解：A
NDPのNS(Neighbor Solicitation, ICMPv6タイプ135)がARP Request、NA(Neighbor Advertisement, ICMPv6タイプ136)がARP Replyに相当します。IPv6にはARPブロードキャストがなく、要請ノードマルチキャストで効率的にMACアドレスを解決します。
