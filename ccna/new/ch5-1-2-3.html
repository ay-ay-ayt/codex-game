5-1 ACL（アクセス制御リスト）

超頻出設定 ACLはCCNA試験の最重要トピックの一つ。設定・適用場所・処理順序を完全理解する

🛡️ACLとは？ ── ルータのファイアウォール機能

ACLは「このパケットを通すか（permit）、拒否するか（deny）」を決めるルールリストです。ルータのインタフェースに適用し、トラフィックをフィルタリングします。

ACLの処理フロー（必ず理解すべき）

パケットがACL適用インタフェースに到着
    ↓
① 最初のACLステートメント（エントリ）と比較
    ↓ マッチしない
② 2番目のステートメントと比較
    ↓ マッチしない
③ 3番目のステートメントと比較
    ↓ マッチした！ → permit なら通過 / deny なら破棄
    ↓ （以降のステートメントは評価しない = 上から順に最初にマッチしたもので決定）
...
全ステートメントにマッチしない場合
    ↓
暗黙のdeny any（最後に自動的に存在）→ パケット破棄！

【重要ポイント】
・ACLは上から順（シーケンス番号順）に評価される
・最初にマッチしたエントリで処理決定（以降は無視）
・末尾に「暗黙のdeny any」が自動で存在 → 明示的にpermitしないと全部拒否される
・ACLは適用しないと効果がない（access-groupコマンドでIFに適用）

📋標準ACLと拡張ACLの違い

比較項目 標準ACL 拡張ACL
番号範囲 1〜99, 1300〜1999 100〜199, 2000〜2699
フィルタ条件 送信元IPアドレスのみ 送信元IP、宛先IP、プロトコル、ポート番号
適用場所 できるだけ宛先に近いインタフェース できるだけ送信元に近いインタフェース
精度 低い（送信元のみで判定） 高い（5タプルで細かく制御）
🚨 ACL適用場所 ── なぜ場所が重要なのか？
標準ACLを送信元近くに置くと問題になる例：
「192.168.1.0/24 からWebサーバー(10.0.0.100)への通信を拒否」したいが、標準ACLは送信元IPしか見ない → 192.168.1.0/24からの全通信（メール、ファイルサーバー含む）がブロックされてしまう！
→ だから標準ACLは宛先近くに置いて影響範囲を最小化する
→ 拡張ACLなら宛先IP＋ポートを指定できるので送信元近くに置いて無駄なトラフィックを早期に遮断する

ワイルドカードマスク ── サブネットマスクとの違い

ワイルドカードマスクは「サブネットマスクの逆」

サブネットマスク:   255.255.255.0   → ネットワーク部のビットが1
ワイルドカードマスク: 0.0.0.255      → チェックしないビットが1

変換方法: 255.255.255.255 - サブネットマスク = ワイルドカードマスク

実例:
  /24(255.255.255.0)   → WC: 0.0.0.255     （最後の8ビットは任意）
  /25(255.255.255.128) → WC: 0.0.0.127     （最後の7ビットは任意）
  /32(255.255.255.255) → WC: 0.0.0.0       （完全一致 = hostキーワード）
  /0 (0.0.0.0)         → WC: 255.255.255.255（全IP = anyキーワード）

特殊なキーワード:
  host 192.168.1.10  = 192.168.1.10 0.0.0.0    （1台だけ）
  any                = 0.0.0.0 255.255.255.255  （全IP）

⚙️ACL設定 ── 実践的な設定例

═══════════════════════════════════════════════
# 【標準ACL ── シンプルだが送信元のみで判定】
═══════════════════════════════════════════════
# 192.168.1.0/24 からのアクセスを許可し、それ以外を拒否
Router(config)# access-list 10 permit 192.168.1.0 0.0.0.255
# ↑ 暗黙のdeny anyにより、192.168.1.0/24以外は全て拒否

# インタフェースに適用（in = 受信方向、out = 送信方向）
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip access-group 10 out

═══════════════════════════════════════════════
# 【名前付き拡張ACL ── 実務で最も使われる形式】
═══════════════════════════════════════════════
Router(config)# ip access-list extended WEB-FILTER

# エントリ1: 192.168.1.0/24 → 10.0.0.100 のHTTP(80)を許可
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.100 eq 80

# エントリ2: 192.168.1.0/24 → 10.0.0.100 のHTTPS(443)を許可
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.100 eq 443

# エントリ3: 全ICMPを許可（ping用）
Router(config-ext-nacl)# permit icmp any any

# 暗黙のdeny anyにより上記以外は全拒否

# 送信元に近いインタフェースのin方向に適用
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip access-group WEB-FILTER in

═══════════════════════════════════════════════
# 【ACL確認・トラブルシューティング】
═══════════════════════════════════════════════
Router# show access-lists
Extended IP access list WEB-FILTER
    10 permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.100 eq www (253 matches)
    20 permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.100 eq 443 (102 matches)
    30 permit icmp any any (45 matches)
# ↑ matchesでどのエントリにどれだけヒットしたか確認できる

Router# show ip interface GigabitEthernet0/0 # ACLが適用されているか確認
  Inbound access list is WEB-FILTER
  Outgoing access list is not set

🔧 ACLトラブルシューティングチェックリスト

  1. ACLの適用方向（in/out）は正しいか？ → inはインタフェースに入ってくるトラフィック、outは出ていくトラフィック
  2. ワイルドカードマスクが正しいか？ → サブネットマスクと間違えていないか
  3. 暗黙のdeny anyを忘れていないか？ → permit文だけ書くと、これ以外は全部拒否される
  4. エントリの順番は正しいか？ → より具体的なルールを先に、一般的なルールを後に
  5. ACLがIFに適用されているか？ → show ip interface で確認

✏️ 確認問題（第5-1章）

Q1. 拡張ACLを適用する推奨場所はどこか？
正解：D
拡張ACLは送信元IP・宛先IP・プロトコル・ポート番号で細かくフィルタリングできるため、不要なトラフィックをできるだけ早い段階で遮断するために送信元に近い場所に適用します。標準ACLは送信元のみで判定するため、宛先近くに置きます。
Q2.【シナリオ】以下のACLを設定したが、192.168.1.0/24のユーザーがインターネットに一切アクセスできなくなった。最も可能性の高い原因はどれか？
access-list 100 deny tcp 192.168.1.0 0.0.0.255 any eq 80
正解：B
このACLは「HTTP(80)を拒否」だけで、他にpermit文がありません。末尾の暗黙のdeny anyにより、DNS(53)、HTTPS(443)、その他すべてのトラフィックがブロックされます。正しくは、deny文の後に「permit ip any any」等を追加する必要があります。
Q3. ワイルドカードマスク 0.0.0.31 は何ホスト分の範囲に一致するか？
正解：C（32ホスト）
ワイルドカードマスク0.0.0.31は2進数で00011111。チェックしないビット（1のビット）が5つ = 2^5 = 32ホスト分に一致します。対応するサブネットマスクは255.255.255.224（/27）です。
Q4. ACLで「host 10.0.0.1」と記述することと同等なのはどれか？
正解：A（10.0.0.1 0.0.0.0）
hostキーワードはワイルドカードマスク0.0.0.0の省略形です。0.0.0.0は「すべてのビットが一致する必要がある」= 完全一致を意味します。Bの255.255.255.255は「any」と同じ意味になるため間違いです。
Q5. 名前付き拡張ACLの利点として正しいのはどれか？
正解：B
番号付きACLはエントリの個別削除ができません（ACL全体を削除して再作成が必要）。名前付きACLはシーケンス番号で個別エントリの追加・削除が可能で、運用管理が容易です。1つのIFの1つの方向にACLは1つだけ適用可能です。

5-2 ポートセキュリティ・DHCP Snooping・DAI

頻出設定 L2レベルでの攻撃を防ぐスイッチのセキュリティ機能

🔒ポートセキュリティ

何を防ぐのか？

不正なデバイスの接続を防ぎます。スイッチのポートに接続できるMACアドレスの数や、特定のMACアドレスを制限できます。

攻撃シナリオ: MACフラッディング攻撃

攻撃者が大量の偽MACアドレスを送信
    ↓
スイッチのMACアドレステーブル（CAMテーブル）が溢れる
    ↓
スイッチが全ポートにフレームをフラッディング（ハブのように動作）
    ↓
攻撃者は本来受け取れないはずのトラフィックを傍受できる！

→ ポートセキュリティで学習できるMACアドレス数を制限して防御

# ポートセキュリティ設定
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode access             # アクセスモード必須！
Switch(config-if)# switchport port-security            # ポートセキュリティ有効化
Switch(config-if)# switchport port-security maximum 2  # 最大2MACアドレスまで許可

# 違反時の動作（3モード）
Switch(config-if)# switchport port-security violation shutdown   # err-disable（デフォルト）
Switch(config-if)# switchport port-security violation restrict   # 不正フレーム破棄 + ログ
Switch(config-if)# switchport port-security violation protect    # 不正フレーム破棄のみ（ログなし）

# MACアドレスの指定方法
Switch(config-if)# switchport port-security mac-address 0011.2233.4455  # 手動指定
Switch(config-if)# switchport port-security mac-address sticky          # 自動学習して保存
# stickyは最初に学習したMACアドレスをrunning-configに保存する

違反モードの比較（超頻出！）

モード 違反フレーム ポート状態 Syslogメッセージ 違反カウンタ
shutdown（デフォルト） 破棄 err-disabled（完全停止） あり あり
restrict 破棄 稼働継続 あり あり
protect 破棄 稼働継続 なし なし
💡 err-disabledポートの復旧方法
手動復旧:  shutdown → no shutdown
自動復旧:  errdisable recovery cause psecure-violation
           errdisable recovery interval 300   (300秒後に自動復旧)

🛡️DHCP Snooping

何を防ぐのか？ ── DHCPスプーフィング攻撃

【攻撃シナリオ】
攻撃者が偽のDHCPサーバーを設置
    ↓
クライアントが偽のDHCPサーバーからIPアドレスを受け取る
    ↓
偽のデフォルトゲートウェイ（攻撃者のPC）が設定される
    ↓
すべてのトラフィックが攻撃者を経由する（中間者攻撃！）
    ↓
パスワードや機密情報が盗まれる

【DHCP Snoopingの防御】
・Trustedポート（正規DHCPサーバー接続）: DHCP応答を許可
・Untrustedポート（クライアント接続）: DHCP応答をブロック
→ 偽DHCPサーバーからの応答はuntrustedポートで拒否される！

# DHCP Snooping設定
Switch(config)# ip dhcp snooping                              # グローバルで有効化
Switch(config)# ip dhcp snooping vlan 10,20                   # 対象VLAN指定

# 正規DHCPサーバーに接続されたポートをTrustedに
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# ip dhcp snooping trust                   # trusted設定

# クライアント側のポートは自動的にuntrusted（デフォルト）
# DHCPレート制限（DoS攻撃防止）
Switch(config-if)# ip dhcp snooping limit rate 15           # 毎秒15パケットまで

Switch# show ip dhcp snooping                            # 設定確認
Switch# show ip dhcp snooping binding                    # バインディングテーブル確認

🔍DAI（Dynamic ARP Inspection）

DAIはARPスプーフィング（ARP偽装）攻撃を防ぎます。DHCP Snoopingバインディングテーブルを参照して、正しいIP-MAC対応かどうかを検証します。

ARPスプーフィングとは

攻撃者が「192.168.1.1(ゲートウェイ)のMACは私のMACアドレスです」と偽のARP応答を送信。被害者のARPテーブルが書き換えられ、トラフィックが攻撃者経由になる中間者攻撃です。 

# DAI設定（DHCP Snoopingが前提条件！）
Switch(config)# ip arp inspection vlan 10,20
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# ip arp inspection trust    # アップリンクをtrustedに

🔑AAA と IEEE 802.1X

AAA（Authentication, Authorization, Accounting）

要素 意味 具体例
Authentication（認証） 「あなたは誰？」（本人確認） ユーザー名+パスワードで確認
Authorization（認可） 「何をして良い？」（権限確認） 管理者はshow running-config可、一般ユーザーは不可
Accounting（アカウンティング） 「何をした？」（操作記録） いつ誰がログインしてどのコマンドを実行したか記録

RADIUS vs TACACS+ 比較

比較項目 RADIUS TACACS+
規格 IETF標準（RFC 2865） Cisco独自（業界普及済）
プロトコル UDP/1812（認証）,1813（アカウンティング） TCP/49
暗号化 パスワードのみ暗号化 パケット全体を暗号化
AAAの分離 認証と認可を統合 認証・認可・アカウンティングを個別に制御可
主な用途 ネットワークアクセス認証（802.1X） ネットワーク機器の管理アクセス認証

IEEE 802.1X ── ポートベース認証

【802.1Xの構成要素】
① Supplicant（サプリカント）: 認証を要求するクライアント（PC）
② Authenticator（オーセンティケータ）: クライアントの接続を制御するスイッチ
③ Authentication Server（認証サーバー）: 認証を実行（通常RADIUSサーバー）

【認証フロー】
PC ──→ [スイッチ] ──→ [RADIUSサーバー]
  EAPメッセージ    RADIUS      認証判定

ポートの状態:
  認証前: 「unauthorized」（DHCP/DNSも通さない ← 802.1X通信のみ）
  認証後: 「authorized」（全通信を許可）

✏️ 確認問題（第5-2章）

Q1. ポートセキュリティ違反時、デフォルトの動作はどれか？
正解：A（shutdown）
デフォルトのviolationモードはshutdownです。ポートがerr-disabled状態になり全トラフィックが停止します。復旧にはshutdown→no shutdownが必要です。
Q2. DHCP Snoopingで偽のDHCPサーバーからの応答をブロックする仕組みはどれか？
正解：C
DHCP SnoopingはDHCP Offer/Ack（サーバー応答）をtrustedポートからのみ許可します。クライアント接続のuntrustedポートからDHCP応答が来たらブロックします。これにより不正DHCPサーバーの動作を防ぎます。
Q3. 802.1Xの3つの構成要素で「認証を実際に実行するサーバー」はどれか？
正解：D
Supplicant=認証を要求するクライアント(PC)。Authenticator=接続を制御するスイッチ（中間役）。Authentication Server=実際の認証判定を行うRADIUSサーバーです。
Q4. TACACS+がRADIUSより優れている点はどれか？
正解：B
TACACS+はパケット全体を暗号化し（RADIUSはパスワードのみ）、AAA3要素を独立して制御できます。TCP/49でより信頼性の高い通信を行います。ただしCisco独自プロトコルです。RADIUSはIETF標準で802.1Xの標準バックエンドです。

5-3 セキュリティの脅威と対策

概念 CCNAで問われるセキュリティの脅威タイプと基本的な対策を理解する

⚠️ネットワークセキュリティの脅威一覧

攻撃カテゴリ 攻撃名 仕組み 対策
偵察（Reconnaissance） ポートスキャン サーバーの開いているポートを調査 IPS/IDS、アクセスリスト
パケットキャプチャ ネットワーク上のパケットを傍受 暗号化（SSH, HTTPS, VPN）
アクセス攻撃 パスワード攻撃（ブルートフォース） 総当たりでパスワードを推測 パスワードポリシー、アカウントロック、MFA
フィッシング 偽のメール/サイトで認証情報を窃取 ユーザー教育、メールフィルタ
中間者攻撃（MITM） 通信を傍受・改ざん 暗号化、証明書検証、DAI
DoS/DDoS攻撃 TCP SYNフラッド 大量のTCP SYNパケットでサーバーリソースを枯渇 SYN Cookie、レート制限
DDoS（分散DoS） 多数のマシンから一斉に攻撃 DDoS防御サービス、ISP連携
L2攻撃 MACフラッディング CAMテーブル溢れによる盗聴 ポートセキュリティ
VLANホッピング DTP悪用でトランク確立、他VLANへアクセス switchport mode access, switchport nonegotiate
🚨 VLANホッピング攻撃の防止策（頻出！）
  • 使用しないポートはshutdownして未使用VLANに割り当て
  • アクセスポートは明示的にswitchport mode accessを設定（DTPによる自動トランク化を防止）
  • トランクポートではswitchport nonegotiateでDTPを無効化
  • ネイティブVLANをVLAN 1以外に変更し、使用しないVLANにする

✏️ 確認問題（第5-3章）

Q1. VLANホッピング攻撃を防ぐための対策として正しくないのはどれか？
正解：C（正しくない対策）
ネイティブVLANをVLAN 1のままにすると、VLANホッピング攻撃の一種（ダブルタギング攻撃）で悪用されやすくなります。ネイティブVLANはVLAN 1以外の使用していないVLANに変更すべきです。
Q2. enable secretとenable passwordの両方が設定されている場合、どちらが使用されるか？
正解：A
enable secretはMD5以上のハッシュで保存され、enable password（type 7、容易に復号可能）より安全です。両方設定されている場合、IOSはenable secretを優先的に使用します。
